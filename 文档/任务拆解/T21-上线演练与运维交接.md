# T21 上线演练与运维交接

**前置**：T20。**范围**：在预发布环境完成容器形态的最终发布验收，以及首次部署、备份恢复、升级回滚和交接文档。

## 实施

- [ ] 在预发布环境激活 `test` profile，按[总流程](./项目搭建与Docker一键部署执行流程.md#9-首次部署默认命令即可)从隔离空库完整部署：仅首次显式开启管理员引导，使用临时密码改密后关闭开关并重新应用配置。生产发布改用 `prod` profile 和独立凭据。
- [ ] 将 T17 的应用功能回归结果与 T20 的 Compose 冒烟合并核对：正式镜像、TLS、同源 Cookie、前后端路径、MySQL/Redis 健康检查、持久卷和密钥注入均须在部署形态下验证。T17 通过不代替本轮发布验收。
- [ ] 演练 MySQL 定时备份和异机恢复；记录应用提交、镜像标签、Flyway 版本与密钥恢复方法。用生产数据副本演练升级迁移。
- [ ] 区分应用镜像回退与数据库恢复；破坏性 schema 变更须先设计兼容发布。交付健康检查、日志查看、证书续期、会话清理、故障处理步骤和实际演练记录。
- [ ] 在隔离环境演练唯一超级管理员离线恢复：核验备份与操作人权限，只恢复原账号，随机临时密码一次性使用、强制改密并撤销旧会话；记录操作，不增加公开恢复接口。

## 验收

- [ ] 部署后验证登录、菜单、关键写入、头像、日志、退出、Redis 数据清空后的验证码失效与登录快照重建、容器重启及 MySQL 持久数据；Redis 进程重启时按实际持久化配置核对未过期键的行为。从外部确认 MySQL、Redis 和明文 8080 未暴露。
- [ ] 完成备份恢复、升级与回滚演练，逐项记录最终发布验收的命令、环境和结果；有失败或外部资源未具备时不得标为可发布。未部署生产时明确写“预发布演练完成”，不声称生产上线。
