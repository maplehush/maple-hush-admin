# T10 用户管理

**前置**：T08、T09。**范围**：`sys_user` 管理及其部门/角色关系。

## 实施

- [ ] 实现 `/api/system/user/**` 分页/详情、创建、修改、状态、删除、角色分配和管理员重置密码；账号 `username` 与 `real_name` 分开，管理页面的 `name` 映射 `real_name`，不能把管理员 `remark` 当作本人 `introduction`。
- [ ] 新建与用户列表重置统一临时密码 `12345678`、标记强制改密；重置仅踢出目标用户，操作管理员保留会话（重置自己除外）。用户列表不得重置唯一超级管理员密码；其本人在个人中心输入旧密码和新密码改密，成功后退出并用新密码重新登录。分配角色与角色范围由 Service 二次校验。
- [ ] 首次引导创建唯一超级管理员账号并关联内置 `super_admin`；用户管理及角色分配接口不得给其他账号授予该角色，也不得移除该账号的内置角色。唯一超级管理员账号不得通过用户管理接口停用、删除、重置密码或改动角色；Service 按角色关联识别并校验，不依赖固定 ID/用户名。批量操作也须整体拒绝含该账号的请求。删除普通用户时先撤销并清理其刷新会话与角色关联，保留登录/操作日志快照，再删除用户；`sys_user.password` 仅存单向哈希，普通列表/详情查询和 VO 均不返回。DTO 不允许直接修改密码哈希、角色权限或 `avatar_url`。
- [ ] 修改资料、状态、角色、重置密码或删除用户后，清理目标用户 Redis 快照；授权或会话变化仍以 MySQL 中的 `authVersion` 和会话撤销为准。

## 验收

- [ ] 真实 MySQL 测试唯一用户名、唯一超管保护、角色越权与并发授予拦截、重置后的旧会话失效及待改密登录；后端 `verify` 通过。
