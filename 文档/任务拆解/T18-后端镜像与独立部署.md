# T18 后端镜像与独立部署

**前置**：T17。**范围**：`backend/` 自己能部署 MySQL、Redis 和单 Jar 后端。

## 实施

- [ ] 编写 `backend/Dockerfile`、`.dockerignore`、`docker-compose.yml`、`.env.example`；镜像仅运行 `admin-system-start` 的唯一可执行 Jar，使用 Java 21 非 root 运行环境。
- [ ] MySQL 使用命名卷；增加 `redis` 服务，后端等待 MySQL 和 Redis 健康后启动。Redis 缓存无需作为业务数据持久化，端口不对公网发布；按[环境配置设计](../架构设计/Redis与环境配置.md)注入连接与密码。开发 Compose 激活 `dev` 并注入 `MYSQL_HOST=mysql`、`REDIS_HOST=redis`；测试/预发布激活 `test`，生产激活 `prod`，分别注入对应环境的地址与密钥。配置健康检查、重启策略、日志限制和受控密钥文件读取；独立部署的公开 API 走 TLS 网关，不直接暴露明文 8080。
- [ ] 检查空库引导开关、`OSS_REGION`、`OSS_BUCKET`、`OSS_PUBLIC_DOMAIN`、`OSS_OBJECT_PREFIX` 等非敏感配置及后端 OSS 凭证的注入方式；不把 `.env`、证书或 secrets 打入镜像，前端服务不接收 OSS AccessKey。

## 验收

- [ ] 在 `backend/` 执行 `docker compose config` 和 `docker compose up -d --build`，检查三个服务健康、数据库卷持久、Redis 连接、liveness/readiness 分工及 API 冒烟；模拟 MySQL 或 Redis 故障时 readiness 下降，liveness 不触发无效重启。重建后数据仍在，缓存可重建。
- [ ] 镜像检查无密钥与无开发产物；记录独立公网 TLS 入口是否实际演练。
