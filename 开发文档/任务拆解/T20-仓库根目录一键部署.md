### 文件与决定

- 根 [docker-compose.yml](../../docker-compose.yml)使用 include 的 path 列表合并两份子 Compose 和对应根覆盖文件。固定服务名 frontend/backend/mysql/redis，不复制服务定义、不设置固定 container_name/全局网络/卷名。
- 根 project_directory 显式设为仓库根；[backend-root.yml](../../deploy/compose/backend-root.yml)修改后端 build.context 与 Redis bind 路径，用 !reset 删除后端宿主机端口；[frontend-root.yml](../../deploy/compose/frontend-root.yml)修改前端 build.context 并固定内部 upstream。使用 !override 替换 Redis bind 列表，因此根部署最低 Compose 版本改为 2.24.4，同步总流程。
- [include.env](../../deploy/compose/include.env)提供非秘密默认值，避免读取子目录 .env。根 [.env.example](../../.env.example)提供项目名、profile、端口、Origin、OSS 和镜像等公开参数；SECRETS_DIR 相对仓库根，支持受控绝对目录。根 upstream 即使外部环境设置了别的地址也固定使用本项目 backend。
- 根模式 backend/mysql/redis 不映射端口，frontend 只映射回环 8090。公开 HTTPS 复用已有前端 TLS 网关；只有四个 Compose 服务。前端与后端无启动依赖，frontend 单侧命令不隐式启动 backend；backend 单侧仍依赖 mysql/redis。空项目仅启动 frontend 不保证可用，首次须整体启动。
- [统一部署说明](../../deploy/README.md)记录开发初始化、首次引导、三个入口、独立/根模式差异、TLS/可信代理和两套同机部署隔离。新增根 secrets/certs 忽略规则，未创建实际密钥或根 .env，未改子项目 Compose，不自动迁移已有卷。

- 复核发现单侧重建后端可能改变 IP，而前端静态解析会继续使用旧地址；补充前端 Nginx 的 Docker DNS（127.0.0.11、缓存 5 秒）与变量 upstream，保留完整 request_uri。独立模式外部域名同样动态解析，并同步前端说明；不改变子 Compose 服务定义。
