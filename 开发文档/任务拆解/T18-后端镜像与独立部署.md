# T18 后端镜像与独立部署

**前置**：T17。**范围**：`backend/` 自己能部署 MySQL、Redis 和单 Jar 后端。

## 实施

- [x] 编写 `backend/Dockerfile`、`.dockerignore`、`docker-compose.yml`、`.env.example`；配置镜像仅运行 `admin-system-start` 的唯一可执行 Jar，使用 Java 21 非 root 运行环境。
- [x] MySQL 使用命名卷；增加 `redis` 服务，后端等待 MySQL 和 Redis 健康后启动。Redis 缓存无需作为业务数据持久化，端口不对公网发布；按[环境配置设计](../架构设计/Redis与环境配置.md)注入连接与密码。开发 Compose 激活 `dev` 并注入 `MYSQL_HOST=mysql`、`REDIS_HOST=redis`；测试/预发布激活 `test`，生产激活 `prod`，使用各自项目内独立的数据服务和密钥。配置健康检查、重启策略、日志限制和受控密钥文件读取；独立部署的公开 API 走 TLS 网关，不直接暴露明文 8080。
- [x] 检查空库引导开关、`OSS_REGION`、`OSS_BUCKET`、`OSS_PUBLIC_DOMAIN`、`OSS_OBJECT_PREFIX` 等非敏感配置及后端 OSS 凭证的注入方式；配置构建上下文排除 `.env`、证书和 secrets，前端服务不接收 OSS AccessKey。

### 文件与设计

- [Dockerfile](../../backend/Dockerfile)：Maven 3.9.9 / Java 21 多阶段构建，构建阶段不连接数据库、不接收运行密钥；运行阶段只复制一个可执行 Jar，使用 Temurin Java 21 JRE、UID/GID 10001 和 exec 入口。`JAVA_TOOL_OPTIONS` 限制堆比例，OOM 时退出；curl 用于 readiness；补充 DejaVu 字体与 headless 模式供 Java2D 验证码使用，实际 Linux 容器验证码仍待验收。
- [Compose](../../backend/docker-compose.yml)：MySQL 8.4 命名卷、Redis 7.4 非持久缓存和后端三服务；无固定容器名/全局卷名。MySQL/Redis 不发布端口，后端只映射回环 8080。依赖健康后启动、120 秒初始化宽限、重启策略、日志轮换、后端/Redis 非 root 与只读文件系统已配置；容器实际行为待引擎验证。
- [环境示例](../../backend/.env.example)只存非秘密配置；本地 IDE 的 `root/123456` 默认值未改。Compose 首次初始化专用 `maple_hush` 账号，默认库仍为 `maple_hush_admin`。`deploy/init-dev-secrets.sh` 仅创建缺失的开发文件，数据库/Redis 开发密码为用户约定的 `123456`，JWT 为随机值。测试/生产需独立密钥，不使用此开发初始化脚本。
- 后端用 `SPRING_CONFIG_IMPORT=configtree:/run/secrets/` 明确读取大写占位符文件。MySQL 用官方 `_FILE` 机制；Redis 用私有临时配置读取密码，处理引号和反斜杠，不把密码放到 argv，禁用 RDB/AOF。OSS 文件可先留空，上传不可用但其余功能可启动；不记录真实 AccessKey。
- [部署说明](../../backend/deploy/README.md)包含首次引导、密钥权限、升级/故障验证和数据保留步骤；[Nginx 示例](../../backend/deploy/nginx-api.conf.example)提供现有宿主机网关的 HTTPS 入口，覆盖外部转发头，只保留一个 `/api`。默认忽略转发头；启用 Tomcat native 转发处理须明确配置真实可信代理 IP 正则，不能信任任意来源。
