# T07 菜单管理

**前置**：T06。**范围**：系统菜单管理树及其路由/按钮规则。

## 实施

- [x] 实现 `/api/system/menu/**` 的管理树、增改删、名称/路径查重；支持 `catalog/menu/embedded/link/button`。`/api/system/menu/list` 的 `data` 对齐 Playground `SystemMenu` 管理树，含字符串 `id/pid`、`name/type/status/path?/component?/authCode?/meta/children?`，保留按钮；与 `/api/menu/all` 的用户路由树使用不同 VO。
- [x] 校验父子关系、路由组件路径、权限码和删除关联；数据库根节点 `path` 使用绝对路径，子节点使用相对路径，同级路径不得重复，并核对拼接后的完整访问地址不冲突。管理树对路由节点输出完整 `path`，普通路由新增/修改接受完整 `path` 并结合 `pid` 转成数据库相对路径；外链不要求提交路由地址，后端按唯一菜单名生成内部路径且允许不选上级目录。`path-exists` 只接收完整路径及可选当前 `id`，按完整访问地址查重，与 Playground 表单调用一致。页面节点可带对应查询权限码，按钮节点必须带操作权限码；按钮须归属页面，目录节点不因包含页面而获得接口权限。`title/icon/sort` 分别生成 `meta.title/icon/order`，`meta_json` 只接受其余白名单字段。同级节点按 `sort ASC, id ASC` 稳定排序。新增节点同步处理内置超管授权；菜单定义在每次请求中参与权限实时计算，菜单增删改不撤销会话。
- [x] 交付 Controller、DTO/VO、Service、Mapper、权限声明，并把关键写操作接入 T06 已落地的操作审计；用真实数据库测试。
- [x] 菜单定义变化后当前请求按数据库重算权限，前端保存/删除成功后重建当前会话的动态路由与菜单；用户角色/角色菜单关联变化仍递增 `authVersion` 并撤销旧会话。
- [x] 系统内置菜单保护：`System` 根目录及其所有后代不可删除；`Dashboard`、`Workspace` 两个基础工作台入口不可删除。概况目录下后来添加的普通子菜单仍可删除，保护同时由管理页操作状态和后端接口校验。

## 验收

## 菜单维护后保持会话（2026-10-21）

- 菜单新增、编辑（包括排序）和删除不再让所有已分配角色的用户 `authVersion` 递增。后端每个请求按最新菜单定义实时计算权限；前端成功后清理并重建动态路由，当前会话保持登录。
- 用户角色或角色菜单授权关系的实际变更仍按 T06/T09 规则递增受影响用户版本并撤销旧会话。
- 回归覆盖菜单写入后旧 access 仍可访问菜单接口、菜单被停用后对应接口权限即刻变为 403；前端类型检查和生产构建通过。

## 前端菜单名称查重校验（2026-10-21）

- 菜单名称必填、格式不合法或空白时不请求名称查重接口，避免空参数触发 400 并把 Axios 原始错误显示为校验文案。
- 查重请求异常显示本地化提示；重复名称继续显示“已存在”提示。

## 前端菜单路由查重校验（2026-10-21）

- 路由地址为空白或格式不合法时不请求路由查重接口；空值显示必填提示，格式错误显示路径格式提示。
- 仅合法静态路由进入查重；查重请求异常显示本地化提示，避免把 Axios 的 Request failed with status code 400 暴露在表单中。


## 新增下级菜单父级回显（2026-10-21）

- 部分接口返回的菜单 ID 为数字，而树选择项值和表单父级值按字符串处理，类型不一致时控件找不到选项标签，退回显示原始 ID。
- 新增下级、编辑回显及树选择项统一将父级 ID 规范为字符串；提交 payload 也规范为字符串。

## 顶层新增菜单类型与父级校验（2026-10-21）

- 工具栏新增默认创建根目录；通过“新增下级”仍根据父节点创建对应子类型。
- 路由和按钮节点必须选择合法父级，目录节点可作为根目录创建，避免默认菜单类型无父级而在保存时才被后端拒绝。
- 菜单管理表单模型测试 18 项通过，目标应用类型检查通过。
