# T16 前端个人中心与演示清理

**前置**：T13～T15。**范围**：目标应用个人中心和最终演示代码清理。

## 实施

- [x] 接通当前用户基本资料、头像上传和本人改密；姓名 `realName` 与个人简介 `introduction` 可编辑并持久化，`username/roles` 仅展示，不允许用户自助修改。本人在个人中心输入旧密码和新密码，改密成功清理令牌并返回登录页，用新密码重新登录；不显示用户列表的临时密码重置入口。
- [x] 用真实接口替换个人中心的 mock 成功提示；无真实功能支撑的演示标签页移除或禁用。
- [x] 系统页面稳定后清理目标应用里不再使用的演示页面和 mock 路径；更新 workspace、锁文件、构建脚本和许可证留存记录。T01 已移除其他四个 UI 应用；用户明确要求 `playground/` 暂留，等整个系统开发完成后再删除。设计区的参考源码只作外部参考，不进入最终仓库。

## 验收

- [x] 浏览器验证资料、头像、本人改密和权限边界；前端 typecheck/build 通过。浏览器采用隔离 API 替身，真实 OSS 上传由用户按先前约定测试。
- [x] 清理目标应用演示路径后重新安装锁定依赖并构建目标应用，确认目标应用运行时无指向 `playground` 或远程 mock 的路径；`playground/` 暂时仍在源码树中。

## 执行记录（2026-10-19）

- `/profile` 改为真实个人中心页面，沿用 Vben `Profile`、`ProfileBaseSetting`、`ProfilePasswordSetting` 与表单 `Upload`。通过 `GET /api/user/info` 加载当前用户；账号和角色只读。资料保存只发送 `realName/introduction` 到 `PUT /api/user/profile`；本人头像选择后立即调用 `POST /api/user/avatar`。头像格式及 2 MiB 大小先由前端提示，实际内容仍由后端校验。
- 修改密码只发送 `oldPassword/newPassword` 到 `PUT /api/user/password`；成功后清除浏览器 access 会话、返回登录页，不再额外请求退出接口。去掉未实现的安全设置、消息通知标签和个人中心占位页。
- 从目标应用删除未启用的官方演示路由、分析/示例页面、虚假登录入口与相应演示语言包；菜单组件候选列表不再提供已删除页面。正式工作台 `/dashboard/workspace`、登录/首次改密、403/404 页面和系统管理页面保留。目标应用源码及环境配置检查无 `playground`、远程 mock 或已删演示路径引用。
- `playground/` 和仅供参考的 `apps/backend-mock/` 按约定保留；目标应用不依赖它们运行。完整 workspace 依赖仍需保留，故 `pnpm-workspace.yaml`、锁文件和构建脚本无需改动；锁定安装结果为 `Already up to date`。`frontend/LICENSE` 与原有 MIT 声明保留。
- 验证：`pnpm install --frozen-lockfile` 通过；`pnpm exec vitest run --dom apps/web-antdv-next/src apps/web-antdv-next/__tests__/unit` 为 15 个文件、64 项通过；`pnpm --filter @vben/web-antdv-next typecheck` 通过；`pnpm --filter @vben/web-antdv-next build` 通过；生产包预览下 `node apps/web-antdv-next/__tests__/e2e/profile.mjs` 通过资料字段限制、普通角色访问、头像接口调用与改密清会话跳转。浏览器用例使用隔离 API 响应，不证明真实 OSS 上传成功或真实 MySQL/Redis 联调；这两项分别按用户约定及 T17 回归处理。未执行 Docker 部署。

## 后续修正（2026-10-20）

- 本次仅做静态差异检查，未运行前端测试、类型检查或构建。

## 移动端布局修正（2026-10-20）

- Vben `Profile` 原布局将摘要栏固定为 `1/6`、内容栏固定为 `5/6`，窄屏下摘要栏被压缩到无法阅读，资料表单也随之变窄。改为移动端纵向堆叠：用户摘要卡片在上方横向展示，基本资料/修改密码页签横向排列，设置内容卡片占满宽度；`md` 及以上仍使用桌面双栏布局。
- 本轮未运行前端构建、类型检查或浏览器验证。
