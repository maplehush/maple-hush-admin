# T04 登录、验证码与首次引导

**前置**：T03。**范围**：图形验证码、两种互斥登录响应、临时密码强制改密和首个超管引导。正常登录在本任务签发初始 access token 与 refresh Cookie；轮换、退出和会话清理由 T05 完成。

## 实施

- [ ] 实现 `GET /api/auth/captcha`、`POST /api/auth/login`、`PUT /api/auth/initial-password`。验证码答案存 Redis，2 分钟 TTL，原子消费一次即删；验证码获取和登录使用 Redis 原子限流。Redis 故障时拒绝跳过验证码或限流。
- [ ] 正常登录一次性生成带令牌族 ID 的短期 JWT access token、高熵 refresh token，`auth_refresh_session` 只保存 refresh 哈希，并按接口契约设置 HttpOnly Cookie；返回前把[最小当前用户快照](../架构设计/Redis与环境配置.md#首版职责)写入 Redis，不得返回一个没有 refresh Cookie 的临时“正常登录”响应。待改密登录只给 5 分钟专用凭据，不给普通 access/refresh 或 Redis 登录快照，两种分支互斥。令牌族有效性校验和退出撤销由 T05 完成。
- [ ] 建立临时密码 `12345678` 的统一哈希与强制改密规则；本任务在首次超管引导中使用。新建用户和管理员重置由 T10 调用同一能力，不在本任务提前实现管理接口。新密码至少 8 字符且不能继续用临时密码，完成后回登录页。
- [ ] `ADMIN_BOOTSTRAP_ENABLED` 默认关闭；首次安装完成 T03 迁移后，仅当 `sys_user` 为空且显式开启引导时创建唯一超管账号，关联已种入的内置角色。关闭开关而 `sys_user` 为空时启动失败；引导完成后启动时校验内置角色恰有一条用户关联且关联用户已启用，异常时拒绝启动，不自动补建。记录登录结果到 `sys_login_log`，日志不含凭据、密码或验证码答案。
- [ ] 实现只在维护模式运行的唯一超管离线恢复命令，不开放 HTTP 入口。恢复命令须可在常规启动因超管停用而拒绝时独立运行；只修改原账号的密码哈希/启用状态/强制改密标记和 `authVersion`，撤销全部会话，不新增第二个超管；使用一次性随机临时密码并记录运维操作，T21 在隔离环境演练。

## 验收

- [ ] 真实 Redis 与 HTTP 测试覆盖验证码正确、错误、过期、并发重复使用、原子限流和 Redis 故障；待改密凭据调用普通 API 被拒绝。
- [ ] 正常登录的响应同时包含 access token 与 refresh Cookie，数据库只含 refresh 哈希，Redis 有带 TTL 的非敏感用户快照；待改密响应不含这两种普通凭据和登录快照。
- [ ] 测试首次引导只执行一次、开关关闭的空库拒绝启动、超管关联为零/多条或账号停用时拒绝启动、密码只保存哈希及强制改密后旧凭据失效；离线恢复仅能作用于原超管账号，恢复后旧会话失效；后端 `verify` 通过。
