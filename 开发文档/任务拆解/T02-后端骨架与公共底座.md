# T02 后端骨架与公共底座

**前置**：T0、T01。**范围**：把 T0 的 Spring Initializr 原始工程改造为后端四模块、单 Jar 和可运行的最薄技术底座。

## 实施

- [ ] 核对 T0 取得的 Initializr 原始工程版本与 Maven Wrapper，验证 Spring Boot 4.1.x 与 MyBatis-Plus Boot 4 starter 的可用组合；不重新引入另一套后台模板。
- [ ] 将原始启动类和资源迁入 `admin-system-start`，建 `backend/pom.xml` 聚合 `admin-base-core`、`admin-system-api`、`admin-system-biz`、`admin-system-start`，保持 [项目结构](../架构设计/后端项目结构.md)规定的依赖方向；只有 `start` 打包可执行 Jar。
- [ ] 落地 `Result<T>`、`PageResult<T>`、统一异常/参数校验、`traceId`、MyBatis-Plus、健康端点与非敏感配置；建立只含 `createTime/updateTime` 的抽象 `BaseEntity` 和东八区秒级时间填充器，主键不放入基类；安装 Maven Wrapper 和测试插件。按[Redis 与环境配置设计](../架构设计/Redis与环境配置.md)加入 Spring Data Redis/Lettuce、连接/序列化/键前缀配置和健康检查，建立 `application.yml`、`application-dev.yml`、`application-test.yml`、`application-prod.yml`，不提交开发密码。`dev` 同时用于宿主机和开发 Compose，Compose 通过环境变量覆盖服务地址。系统表查询、认证业务和完整授权留给后续任务。

## 验收

- [ ] `./mvnw.cmd verify`（Windows）或 `./mvnw verify`（其他环境）实际通过；检查依赖无环，仅有一个可执行 Jar。
- [ ] 用本地 MySQL 和 Redis 在 `dev` 配置下启动并验证连接、健康端点及地址覆盖；liveness 仅检查应用自身，readiness 显式检查 MySQL/Redis。校验 `test`/`prod` 缺少必需连接参数时不会意外连接开发服务。开发 Compose 的实际启动留给 T18 验证；若版本组合不兼容，先修复并同步更新架构文档，不以依赖下载成功代替启动验证。
