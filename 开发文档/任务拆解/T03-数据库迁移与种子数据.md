# T03 数据库迁移与种子数据

**前置**：T02。**范围**：Flyway 首版数据模型及系统基础数据；不实现管理 HTTP 接口。逐字段说明见[数据库表结构](../架构设计/数据库表结构.md)，两份 SQL 草案分别是[建库建表](./T03-01-建库建表草案.sql)和[初始化系统基础数据](./T03-02-系统基础数据草案.sql)。草案已在 T03 整理为后端工程的 V1/V2 迁移；部署时只运行 Flyway，不单独执行草案。

## 实施

- [x] 默认使用 `maple_hush_admin` 数据库。部署侧先创建空数据库与受限账号（Compose 首次启动可自动创建；连接已有 MySQL 时由具备权限的操作者创建），后端数据源指向该库。Flyway 迁移不包含 `CREATE DATABASE` 或写死 `USE maple_hush_admin`，以便第二套实例使用独立库名。
- [x] 以[第一份 SQL 草案](./T03-01-建库建表草案.sql)为起点，先按 T01 确认的实际 Vben 版本和实体字段复核，再在 `admin-system-start/src/main/resources/db/migration/` 建全项目唯一版本序列。移除草案中的 `CREATE DATABASE` 和 `USE`，只将建表部分整理为 `V1__create_system_tables.sql`；数据库由部署配置创建和选择，Flyway 不写死库名。草案含 11 张系统、会话和日志表；`sys_user.password` 只存单向密码哈希，`real_name` 映射前端 `name/realName`，`introduction` 与管理员 `remark` 分开，`avatar_url` 可为空，临时密码标志为 `must_change_password`。
- [x] 以[第二份 SQL 草案](./T03-02-系统基础数据草案.sql)为起点，移除 `USE` 和供手工执行的显式事务包装，在单独的 `V2__seed_system_data.sql` 迁移中种入内置 `super_admin` 角色、系统管理目录、七个页面、操作按钮节点及其 `sys_role_menu` 授权关系。页面节点带查询权限码，按钮节点带操作权限码，目录节点不因承载子路由而获得业务接口权限。前四个页面的路由名和 `list.vue` 文件参考 Playground；字典与两种日志页面统一采用本项目的 `list.vue` 约定；数据库 `component` 保存不带 `.vue` 后缀的 Vben 页面键，例如 `/system/user/list`。路由路径、`component` 和权限码以 T01 核对的前端版本和接口契约清单为准；T14 建立与最终种子路径一致的最小页面组件，T15 完成真实页面。迁移脚本不写用户和密码。复核草案中的 `BIGINT` 主键、`DATETIME` 秒级精度、东八区时间约定、统一的 `_time` 时间列命名、树根映射和唯一范围；固定并验证应用与 MySQL 会话时区，确保 `CURRENT_TIMESTAMP` 的默认值符合东八区约定。
- [x] 为用户名、角色编码、字典值、授权关联、过期会话等建立与查询匹配的约束和索引；菜单 `name` 和非空 `auth_code` 全表唯一，`path` 在同一父节点下唯一，根节点的 `NULL parent_id` 须归一后参与查重，实际访问地址另由 Service 校验。真实 MySQL 验证根节点、同级重名路径与不同目录下相同子路径的行为。部门/菜单的自引用只能约束直接父节点存在，深层循环由 Service 校验；六个含 `create_time/update_time` 的系统主表实体继承 `BaseEntity`，仅有 `create_time` 的其余实体自行声明该字段。实体的布尔属性不以 `is` 开头：`SysRole.builtIn` 显式映射 `is_builtin`，`SysDictItem.defaultItem` 显式映射 `is_default`；实体、Mapper 映射只做后续任务所需的最小读取能力。

## 验收

- [x] 真实 MySQL 验证空库迁移、第二次启动幂等和升级迁移路径；核对继承字段及 `is_builtin`、`is_default` 的实体读写映射、唯一约束及索引。用已知东八区时间验证秒级写入/读取不偏移，覆盖实体插入/更新、Wrapper-only 更新及自写 SQL 写入，核对 `@@session.time_zone`、数据库默认值、`ON UPDATE CURRENT_TIMESTAMP` 和 `LocalDateTime` 的 `yyyy-MM-dd HH:mm:ss` JSON 序列化。实际前端日期组件的展示与时区往返留给 T14 联调、T17 回归，T03 不宣称浏览器展示已通过。
- [x] 核对 V1/V2 的先后关系、实际七个前端页面的路由与 `component`、每个按钮权限码和 `sys_role_menu` 的授权覆盖；在正式环境由 Flyway 执行迁移，不先手工执行两份草案，以免出现已建表但缺失 Flyway 历史记录的冲突。
- [x] 执行后端 `verify`；数据库内没有明文临时密码或预置管理员用户。
- [x] T03 完成后，库中已有内置角色、基础菜单和按钮权限，但 `sys_user` 仍为空；没有演示用户、演示部门、字典项或预制日志。首个超级管理员留待 T04 显式引导创建。

建表以 [MySQL 8.4 的 `CREATE TABLE` 语法](https://dev.mysql.com/doc/refman/8.4/en/create-table.html)为目标；`CHECK` 约束不能引用 `AUTO_INCREMENT` 列，因此树节点的自引用和循环校验保留在 Service 中，详见 [MySQL `CHECK` 约束说明](https://dev.mysql.com/doc/refman/8.4/en/create-table-check-constraints.html)。本轮已在本机 MySQL 8.0.24 验证，目标 MySQL 8.4 环境仍须在 T17/T18 复验。
