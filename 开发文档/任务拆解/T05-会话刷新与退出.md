# T05 会话刷新与退出

**前置**：T04。**范围**：在 T04 已签发的初始 access/refresh 会话上实现轮换、退出、失效与清理，不重新定义登录响应。

T04 已落地 `mh_refresh` Cookie、`AuthTokenService`、`AccessTokenFilter` 和 `auth_refresh_session` 初始写入；本任务直接延续这些组件。当前 Cookie 写接口尚未启用 CSRF 防护，T05 实施时须先补齐并验证。

## 实施

- [ ] 实现 `POST /api/auth/refresh` 的原子轮换和 `POST /api/auth/logout` 撤销；`auth_refresh_session` 仅存 refresh 哈希。access token 带令牌族 ID，请求鉴权须确认族中仍有有效会话；退出撤销当前令牌族，使该族已签发的 access 在下一次请求失效，刷新轮换则不误伤同族仍未过期的 access。旧 refresh 第二次提交时拒绝、撤销该令牌族并记录安全事件，避免出现两个有效后继 token。
- [ ] 生产 refresh Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`、host-only、`Path=/api/auth`；新增匿名 `GET /api/auth/csrf` 返回 `data.token` 并设置同源 CSRF Cookie，refresh/logout 须带 `X-XSRF-TOKEN` 与 Cookie，同时校验请求来源。CSRF 缺失或无效返回 HTTP 403 和稳定业务码，不触发 access refresh；登录或退出使 CSRF 凭据重置后须重新获取。后端按选定 Spring Security 版本验证 SPA token 处理和 Cookie 生命周期。退出由 refresh Cookie 的哈希定位并撤销会话族，不能要求未过期 access；无有效 refresh 时仍幂等清除 Cookie，过期 access 不阻止退出；刷新成功响应保留 Vben 当前读取的原始 token 字符串特例。
- [ ] access 默认 15 分钟、refresh 令牌族绝对有效期默认 7 天；轮换后的记录继承族原定 `expire_time`，Cookie 到期与数据库一致。旧记录至少保留至令牌族到期以支持重放检测，再按可配置留存期清理。实现 `authVersion` 校验基础能力；会话失效时区分 401 与 403。
- [ ] refresh 轮换始终以 MySQL 会话为准；成功后可重建 Redis 用户快照。退出、本人改密和会话撤销清理关联快照；缓存丢失时从 MySQL 恢复，旧 token 不得因缓存残留重新有效。

## 验收

- [ ] 测试 T04 正常登录产生的初始会话、刷新、并发提交同一旧 refresh、重放后的令牌族撤销、退出后旧 access 立即失效、access 已过期仍能退出、刷新后同族未过期 access 保持有效、令牌族绝对到期及旧记录留存、Cookie/CSRF 获取与重置、会话清理、Redis 快照清理和重建；T04 首次改密后旧凭据失效。管理员重置后的会话失效由 T10 验收，前端多标签页协调由 T14 验收。
- [ ] 后端 `verify` 通过；日志和数据库没有 refresh 明文。
