# T05 会话刷新与退出

**前置**：T04。**范围**：在 T04 已签发的初始 access/refresh 会话上实现轮换、退出、失效与清理，不重新定义登录响应。

T04 已落地 `mh_refresh` Cookie、`AuthTokenService`、`AccessTokenFilter` 和 `auth_refresh_session` 初始写入；本任务直接延续这些组件。T05 已在此基础上启用 Cookie 写接口的 CSRF 与来源校验，初始签发也复用事务化会话服务。

## 实施

- [x] 实现 `POST /api/auth/refresh` 的原子轮换和 `POST /api/auth/logout` 撤销；`auth_refresh_session` 仅存 refresh 哈希。access token 带令牌族 ID，请求鉴权须确认族中仍有有效会话；退出撤销当前令牌族，使该族已签发的 access 在下一次请求失效，刷新轮换则不误伤同族仍未过期的 access。旧 refresh 第二次提交时拒绝、撤销该令牌族并记录安全事件，避免出现两个有效后继 token。
- [x] 生产 refresh Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`、host-only、`Path=/api/auth`；新增匿名 `GET /api/auth/csrf` 返回 `data.token` 并设置同源 CSRF Cookie，refresh/logout 须带 `X-XSRF-TOKEN` 与 Cookie，同时校验请求来源。CSRF 缺失或无效返回 HTTP 403 和稳定业务码，不触发 access refresh；登录或退出使 CSRF 凭据重置后须重新获取。后端按选定 Spring Security 版本验证 SPA token 处理和 Cookie 生命周期。退出由 refresh Cookie 的哈希定位并撤销会话族，不能要求未过期 access；无有效 refresh 时仍幂等清除 Cookie，过期 access 不阻止退出；刷新成功响应保留 Vben 当前读取的原始 token 字符串特例。
- [x] access 默认 15 分钟、refresh 令牌族绝对有效期默认 7 天；轮换后的记录继承族原定 `expire_time`，Cookie 到期与数据库一致。旧记录至少保留至令牌族到期以支持重放检测，再按可配置留存期清理。实现 `authVersion` 校验基础能力；会话失效时区分 401 与 403。
- [x] refresh 轮换始终以 MySQL 会话为准；成功后可重建 Redis 用户快照。退出、本人改密和会话撤销清理关联快照；缓存丢失时从 MySQL 恢复，旧 token 不得因缓存残留重新有效。

## 本次执行记录（2026-10-13）

- 实现 `GET /api/auth/csrf`、`POST /api/auth/refresh`、`POST /api/auth/logout`。refresh 成功正文为 JSON 字符串，沿用 Vben `baseRequestClient` 的原始 token 读取约定；logout 用 `Result` 返回 `data:null`，不依赖 access，缺少或无效 refresh 仍可在有效 CSRF/来源校验后幂等清除 Cookie。当前前端仍为上游调用，CSRF 获取、请求头和多标签页刷新协调按 T14 实施。
- `AuthSessionService` 与 `AuthSessionMapper` 管理初始签发、MySQL 行锁轮换和整族撤销；统一先锁用户、再锁旧会话。旧 token 只产生一个后继记录；有效期内重放先提交整族撤销，再返回 401 并写 `REFRESH_REPLAY` 审计。V3 为会话增加 `auth_version` 并回填原记录，新签发和轮换保存用户当前版本；停用、待改密、版本变化或族到期均拒绝刷新。默认开发库已从 V2 升级至 V3；未改 V1/V2 及现有超管密码。
- 使用实际依赖 Spring Security `7.1.1` 的 Cookie CSRF repository 与 XOR request handler；预期值位于 `mh_csrf` HttpOnly Cookie，JSON 给出经 XOR 处理的提交值，只接受 `X-XSRF-TOKEN`。登录、首次改密和退出清除旧 CSRF，refresh 401 清除两类 Cookie，503 保留原 Cookie 供重试。响应同时保留多个 `Set-Cookie`；真实 Tomcat 用过去的 `Expires` 删除 CSRF Cookie，测试按解析后的过期语义验收。[官方 CSRF 说明](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。
- 登录/刷新/退出使用精确 Origin 白名单，缺少 Origin 时回退校验 Referer，两者都缺少或来源不符为 40301。`dev` 默认允许目标 Vben 的 `localhost/127.0.0.1:5999` 和后端自身来源；`test/prod` 必须通过 `AUTH_ALLOWED_ORIGINS` 注入正式公开来源，不信任 Host/转发头推导生产白名单。生产 Cookie 均为 host-only、`Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/api/auth`；refresh Cookie 的 Max-Age 不超过 MySQL 绝对族到期时间。
- 正常登录与轮换成功前从 MySQL 重建 Redis 最小快照；快照写失败回滚会话事务并返回 503，旧 refresh 仍可重试。退出与重放先完成 MySQL 撤销，缓存清理失败只记日志，撤销仍有效。登录、退出和重放审计使用独立事务，日志提交失败不改变已完成的会话结果。清理任务默认每小时分批运行，仅删除族到期后超过 7 天留存期的记录，支持 `AUTH_SESSION_RETENTION_DAYS`、`AUTH_SESSION_CLEANUP_DELAY_MS` 覆盖；有效族中的已用/已撤销哈希不会提前删除。
- 在 `backend/` 设置 `T04_IT_ENABLED=true`、`T05_IT_ENABLED=true`，执行 `./mvnw.cmd -ntp verify`：五个 Reactor 模块成功，15 项单元测试与 13 项真实集成测试通过，3 项需另启用的 T03 IT 跳过。覆盖并发 refresh、重放族撤销、轮换后原 access 仍有效、实际过期 access 退出、绝对族到期、版本失效、Cookie/CSRF 重置、Origin/Referer 与参数替代拒绝、留存清理、Redis 快照重建及故障回滚，同时回归 T04 登录和首次改密。另用临时隔离库运行 `T03_IT_ENABLED=true` 与 `-Dit.test=SystemMigrationIT` 的 `verify`，3 项 V1～V3 迁移/映射/约束测试通过；该库已删除。T05 会话测试自建的随机隔离库也在结束后删除。未运行 MySQL 8.4、Docker、真实浏览器联调或正式部署。
