# T09 角色管理

**前置**：T07。**范围**：角色 CRUD、菜单授权与内置角色保护。

## 实施

- [x] 实现 `/api/system/role/**` 的列表、增改删与菜单授权；稳定 `role_code` 唯一，管理页面的 `name` 映射 `sys_role.role_name`，前端提交菜单节点 ID，不提交后端最终权限码。
- [x] 内置 `super_admin` 不可删、停用或普通改授权；非超管仅能授予自身持有的有效菜单权限。删除普通角色前处理 `sys_user_role`、`sys_role_menu` 关联并使原持有用户的 `authVersion` 失效；授权变更也在业务事务中更新受影响用户 `authVersion`。
- [x] 角色授权以页面和按钮节点 ID 为输入：授予页面时补齐目录祖先，授予按钮时要求其所属页面也被授予；移除页面时一并移除其下按钮。仅补齐目录不增加接口权限。角色或菜单状态变更导致有效权限变化时，也要使受影响用户的旧 token 失效。
- [x] 清理受影响用户的 Redis 当前用户快照；清理失败时，MySQL `authVersion` 校验仍须使旧 token 失效。
- [x] 交付 Controller、DTO/VO、Service、Mapper、权限码、审计和必要测试。

## 验收

- [x] 测试重复编码、越权授予、孤立按钮拒绝、目录祖先补齐、移除页面时清理按钮、内置角色保护、并发授权与旧 token 失效；后端 `verify` 通过。
