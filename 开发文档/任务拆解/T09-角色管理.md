# T09 角色管理

**前置**：T07。**范围**：角色 CRUD、菜单授权与内置角色保护。

## 实施

- [x] 实现 `/api/system/role/**` 的列表、增改删与菜单授权；稳定 `role_code` 唯一，管理页面的 `name` 映射 `sys_role.role_name`，前端提交菜单节点 ID，不提交后端最终权限码。
- [x] 内置 `super_admin` 不可删、停用或普通改授权；非超管仅能授予自身持有的有效菜单权限。删除普通角色前处理 `sys_user_role`、`sys_role_menu` 关联并使原持有用户的 `authVersion` 失效；授权变更也在业务事务中更新受影响用户 `authVersion`。
- [x] 角色授权以页面和按钮节点 ID 为输入：授予页面时补齐目录祖先，授予按钮时要求其所属页面也被授予；移除页面时一并移除其下按钮。仅补齐目录不增加接口权限。角色或菜单状态变更导致有效权限变化时，也要使受影响用户的旧 token 失效。
- [x] 清理受影响用户的 Redis 当前用户快照；清理失败时，MySQL `authVersion` 校验仍须使旧 token 失效。
- [x] 交付 Controller、DTO/VO、Service、Mapper、权限码、审计和必要测试。

## 验收

### 角色状态快捷更新接口（2026-10-20）

- 新增 `PUT /api/system/role/{id}/status`，DTO 只接收 0/1 状态；不会覆盖角色资料或菜单授权。
- 沿用角色更新权限；停用角色需要 `system:role:grant` 才能启用，且重新校验现存授权范围。内置角色仍不可切换；变更审计为 `system:role:update`，授权版本和缓存按原角色状态变更机制处理。
- Maven 隔离 HTTP/MySQL/Redis 回归验证结果见本次 T15 补充记录；首次未配置测试环境变量的运行未能启动，补齐本机隔离测试配置后继续。

## 工作台基础入口调整（2026-10-21）

工作台不作为角色权限。角色授权界面不展示“概览 / 工作台”，角色服务过滤该保留节点；V9 清理已有授权关系。工作台继续由认证后的基础菜单返回，用户无角色时仍能进入工作台，但不会因此拥有管理菜单或接口权限。实现记录见 [T06](./T06-接口权限与动态路由.md#默认工作台入口2026-10-21)。

## 授权树父子联动恢复（2026-10-21）

2026-10-15 迁移 Playground 角色页时额外加入了 `check-strictly`，使授权树父子节点变为独立勾选；迁移前的 Playground 未设置该属性。恢复父子级联勾选。角色详情包含用于导航的目录祖先 ID；前端初始化时不直接采用这些目录 ID，而是按可授权子节点重建全选目录，部分选中目录由树显示为半选，避免回显成未勾选。用户修改勾选时由树执行父子级联。目录本身不新增接口权限，提交时仍由后端校验并规范化目录祖先。
