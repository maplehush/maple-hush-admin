## 使用方式

1. 每次只指定一张任务卡，例如“开始执行 T0”。执行者先读本索引、该任务卡、[总体架构](../架构设计/总体架构.md)、[项目结构](../架构设计/后端项目结构.md)、[开发规范](../开发规范/后端开发规范.md)和[总流程](./项目搭建与Docker一键部署执行流程.md)，再检查工程真实状态。
2. 一个任务完成后提交可审查的文件变更、实际验证命令及结果、未解决问题；下一任务由用户另行发起。任务卡里的“验收”是未来执行标准，不代表现在已经通过。
3. 如上游版本、仓库结构或已落地代码与任务卡不同，先核对并更新受影响任务卡及架构文档，再实施；不机械照抄过时路径。单个任务内部可继续拆成编码步骤，但不得越过任务边界预做后续功能。
4. 测试随实现任务落地。T17 是镜像前的应用功能回归，T20/T21 验证容器部署与最终发布条件；它们都不是前面任务免测的理由。任何失败都先修复，再报完成。
5. 任务卡中的人工前置资源（阿里云 OSS、域名、证书、服务器）只有在相应阶段真正需要时才准备。不得把凭据写进任务文档、代码、镜像或提交记录。
