# 前后端优化记录（2026-10-22）

本轮由用户明确授权执行整体审查列出的六项优化，沿用现有模块和接口。

## 实施内容

1. 用户管理测试隔离部门 API，避免纯表单边界测试加载网络和认证副作用；Tag 改为现有组件的独立入口引用。保持业务函数位于 `data.ts`。
2. 根目录 `.github/workflows/ci.yml` 建立本项目流水线，覆盖 main/develop 的 push 与 PR。前端使用工程声明的 Node/pnpm、冻结锁文件安装，以及 ESLint、Oxfmt、typecheck、目标测试和构建；后端使用 Java 21 和 Maven Wrapper 执行 verify。仅授予仓库读取权限，同分支新检查取消旧检查。前端原有嵌套工作流已在后续目录整理中移除，项目 CI 统一使用仓库根目录工作流。
3. 请求方法不支持时返回 HTTP 405、`BAD_REQUEST` 与 Allow 头；参数类型转换失败返回 HTTP 400、`INVALID_ARGUMENT`，未知异常继续返回安全 500。
4. `UploadRateLimiter` 复用现有 Redis，Lua 原子检查账户分钟与 24 小时固定窗口，统一上传和个人头像共用次数。默认每分钟 10 次、每 24 小时 100 次，窗口从首次预占开始计时；配额预占后发生的失败仍计数。Redis 不可用或脚本无结果时拒绝上传并返回 503，达到配额返回 429，拒绝继续写 OSS。
5. 权限加载把有效角色与直接授权 ID 合并为一次 LEFT JOIN，保留没有菜单的有效角色，并去重菜单 ID。授权上下文从三次 SQL 降为两次，继续实时读取；已有 auth_version 检查及授权图计算沿用原逻辑。
6. 增加前端共享错误码文案解析器和中英文 `errors.json`。中文保留后端具体业务说明，英文按稳定错误码显示本地化提示；登录凭据错误与会话过期分别处理，未知响应和网络错误使用本地化兜底。同步请求拦截器、认证传输和认证 Store 的相关提示。
