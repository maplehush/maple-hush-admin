# T10 用户管理

**前置**：T08、T09。**范围**：`sys_user` 管理及其部门/角色关系。

## 实施

- [x] 实现 `/api/system/user/**` 分页/详情、创建、修改、状态、删除、角色分配和管理员重置密码；账号 `username` 与 `real_name` 分开，管理页面的 `name` 映射 `real_name`，不能把管理员 `remark` 当作本人 `introduction`。
- [x] 新建与用户列表重置统一临时密码 `12345678`、标记强制改密；重置仅踢出目标用户，操作管理员保留会话（重置自己除外）。用户列表不得重置唯一超级管理员密码；其本人输入旧密码和新密码的个人中心改密由 T13 落实，成功后退出并用新密码重新登录；T10 不增加替代入口。分配角色与角色范围由 Service 二次校验。
- [x] 首次引导创建唯一超级管理员账号并关联内置 `super_admin`；用户管理及角色分配接口不得给其他账号授予该角色，也不得移除该账号的内置角色。唯一超级管理员账号不得通过用户管理接口停用、删除、重置密码或改动角色；Service 按角色关联识别并校验，不依赖固定 ID/用户名。本轮不新增批量接口；后续新增批量操作时须整体拒绝含该账号的请求。删除普通用户时先撤销并清理其刷新会话与角色关联，保留登录/操作日志快照，再删除用户；`sys_user.password` 仅存单向哈希，普通列表/详情查询和 VO 均不返回。DTO 不允许直接修改密码哈希、角色权限或 `avatar_url`。
- [x] 修改资料、状态、角色、重置密码或删除用户后，清理目标用户 Redis 快照；授权或会话变化仍以 MySQL 中的 `authVersion` 和会话撤销为准。

## 本轮实施安排（2026-10-14）

1. 先编写真实 HTTP/MySQL/Redis 的用户管理测试，观察未实现端点失败。
2. 实现用户 DTO/VO、`ISysUserService` 与 `SysUserServiceImpl`、Controller 和受控 Mapper；管理读取显式排除密码字段。
3. 在已有共享结构锁下锁定操作者/目标用户，校验唯一超管关联及角色可授予范围；事务内更新版本/会话，提交后清理缓存并写入审计。
4. 执行 T10 专项及全量后端回归，独立审查，更新契约/架构/交接/任务状态并提交。

本轮裁定：

- 不新增批量 API；契约仅列单用户接口。后续若新增批量写入，必须在同一事务预检全部目标，含超管即整体拒绝。
- 创建普通用户的角色可选，仅要求 `system:user:create`；实际分配角色时额外要求 `system:user:assign-role`，只接受现存启用的普通角色。角色全量替换允许保留原已关联停用角色；不允许内置角色或 `super_admin`。普通操作者只能管理权限范围内的目标用户，并只能分配本人有效菜单范围内的角色，防止通过重置高权限账号密码间接提权。
- 启用停用用户会恢复其已有角色能力，因此除 update 权限外，还需要 assign-role 权限并复核当前角色范围。
- 资料修改仅清理快照；状态、角色、重置导致版本递增并撤销目标会话；删除先撤销/清理会话和角色关系，保留日志快照。本人资料/头像/旧密码改密属于 T13，不在 T10 预做。
- 更新是资料全量表单：name 必填，deptId 为空/0 清除部门，remark 为空清除备注；status 省略/null 保留。账号、角色、密码、头像不由该 DTO 修改。

执行进度：七个接口已实现；T10 的 13 个真实集成测试、全量后端回归及独立审查已完成。

## 新建用户角色必选（2026-10-21）

> 历史规则，已由下方 2026-10-27 的角色选填调整替代。

- 新建普通用户的 `roleIds` 必填且至少包含一个角色；后端 DTO 与 Service 双重校验，创建接口同时要求 `system:user:create` 和 `system:user:assign-role`。
- 更新现有用户的独立角色全量替换接口仍允许空数组清空角色；超级管理员仍仅由首次引导创建，不走普通用户表单。
- 新增集成测试覆盖空数组和缺少 `roleIds` 的拒绝行为；通过 `UserManagementIT` 15 项真实 MySQL/Redis 用例，空角色与缺少字段均返回 400，权限不足仍拒绝创建。


初始 RED：UserManagementIT 在端点尚未实现时出现预期 404；同时修正测试夹具将部门列误写为 dept_name 的问题（实际为 name）。首轮实现测试发现无效日期未转业务错误、未知字段被默认忽略，以及认证测试缺少 Origin；分别在用户查询 DTO 捕获日期异常、用户写 DTO 显式拒绝未知字段、测试请求遵守既有 Origin 策略后，10 个专项测试全部通过。

审查裁定：角色全量替换应区分新增角色与原关联；保留已停用的原角色不构成新增授权，同一集合重提保持幂等，新授予停用角色仍拒绝。新增第 13 个真实集成测试先验证当前返回 400 的边界，再修正差集校验并重新回归。

## 新建用户角色选填（2026-10-27）

- 用户确认新增账号可以先不分配角色，之后独立授权。`roleIds` 省略/null/空数组均创建无角色账号；实际传入角色时仍校验分配权限、角色启用状态、内置角色及授权范围。
- 创建无角色账号仅需 `system:user:create`；默认临时密码和首次改密流程保持原约定，改密后只能访问基础工作台。
- 对应 `UserManagementIT` 改为验证空数组/省略/null 可创建、无关联写入，以及只有创建权限时可创建无角色账号但不能分配角色；使用隔离测试库验证，不修改现有业务账号。
- RED：前端两项新增用例因角色必填失败，后端两项新预期均得到 HTTP 400；修正后 GREEN。
- 前端：`pnpm exec vitest run apps/web-antdv-next`，22 个文件、97 项通过；最终用户表单专项复跑 10 项通过；目标应用 typecheck、production build、源码 ESLint、源码 `oxfmt --check` 和 `git diff --check` 均通过。构建保留既有 BigInt 浏览器目标警告。
- 后端：Java 21，设置 `T10_IT_ENABLED=true`、`T06_IT_ENABLED=true` 及本地 MySQL/Redis 测试环境变量后，在 `backend/` 执行 `mvnw.cmd -B -ntp "-Dit.test=UserManagementIT,PermissionFlowIT" "-Dfailsafe.failIfNoSpecifiedTests=false" verify`，46 项单元测试、24 项真实 HTTP/MySQL/Redis 集成测试（用户管理 15、权限流程 9）通过，reactor BUILD SUCCESS。测试使用随机隔离 schema 和 Redis 前缀并清理隔离库。
- 本轮未运行浏览器手工交互和 Docker 构建/部署；服务器需更新前后端镜像后验收。未新增数据库迁移。
