# T14 前端登录与动态权限

**前置**：T06 和 T01 的前端基线。**范围**：`apps/web-antdv-next` 登录、会话与路由；只建立系统菜单所需的最小页面组件入口，七个系统页面的真实查询与写操作留给 T15。

## 实施

- [ ] 登录页保留用户名、密码，加入服务端图形验证码；移除演示账号选择、自动填入演示密码与 `SliderCaptcha`。
- [ ] 对接正常登录/待改密两种互斥响应；待改密只进专用页面，成功后回登录页。实现 access 过期刷新、退出与 401/403 处理，不把待改密凭据存为普通 access。按 T01 契约通过 `GET /api/auth/csrf` 获取 token；刷新和退出同时携带 refresh Cookie 与 `X-XSRF-TOKEN`，退出可附带当前 access token，但 access 已过期时仍须能通过 refresh Cookie 与 CSRF 完成退出和本地状态清理。登录或退出后重新获取 CSRF 凭据；CSRF 失败的 403 不进入 refresh 循环。同一页面的并发 401 只触发一次 refresh；同源多标签页协调刷新并分发新 access token，协调失败时要求重新登录，不重复使用旧 refresh。
- [ ] 使用 `accessMode: 'backend'` 获取 `/api/menu/all` 与 `/api/auth/codes`；开发代理和生产路径仅有一个 `/api` 前缀，关闭 mock 调用。为后续从 Playground 移植的用户、角色、菜单、部门页面先建立相同的 `system/*/list.vue` 入口；字典与两种日志页面按 T03 最终种子路径新增 `list.vue`。这些入口在本任务只保证路由可加载，明确显示功能仍待 T15 完成，不提供虚假的查询数据、操作按钮或成功提示；T15 在相同路径实现真实页面。

## 验收

- [ ] 浏览器验证验证码刷新/失败、初次改密、正常登录、同页并发 401、同源多标签页刷新、CSRF 凭据获取/失效、退出后旧 access 被拒绝、不同权限的路由；用已知东八区时间样例核对前端日期组件不会把后端 `yyyy-MM-dd HH:mm:ss` 再当 UTC 加八小时。系统菜单均能加载对应最小组件，不宣称 CRUD 或全部按钮已可用。按钮可见性与业务页面的完整验收留到 T15。
- [ ] 执行目标应用 typecheck 与 build，记录命令及结果；没有运行的浏览器场景不得写“已通过”。
