# HTTP 登录与会话兼容修复

## 用户已确认的目标

支持 IP + HTTP 登录、首次改密、刷新和退出，取消 Web Locks 的硬性依赖；错误提示区分认证失败与前端会话处理失败。正式部署仍建议 HTTPS，但不以证书绕过本次实现缺陷。

## 实施方案

- 保留 `SessionCoordinator` 的同页面 pending 合并、共享会话代次及旧响应隔离。
- 用 HTTP 下可用的 `crypto.getRandomValues` 生成非凭据的会话代次标识，不再调用 `crypto.randomUUID`。
- 用 IndexedDB 同一对象仓库的 readwrite 事务串行化跨标签页认证操作；事务持有期间持续排队一个读取请求，直到网络操作完成才释放。不同页面共享数据库，因此无需 Web Locks 或有过期竞争风险的 localStorage 租约。数据库不存放密码或令牌。
- 不改后端 refresh 协议和旧令牌重放撤销规则。浏览器禁止存储或协调不可用时，明确提示会话环境异常，不偷偷并发刷新。
- 登录页保留后端返回的认证错误；网络、会话存储及前端异常不再统一误报账号密码错误。

## 执行步骤与验证

1. 先补充无 randomUUID/Web Locks 的浏览器环境回归测试，验证当前实现失败。
2. 实现会话标识和 IndexedDB 协调，测试双页面并发、操作失败后的释放、等待超时和不可用场景。
3. 修正登录提示并执行相关单元测试、目标 typecheck/build。
4. 使用真实浏览器验证 HTTP 非安全上下文下登录、首次改密、刷新、退出及双页面协调。模拟接口和真实后端验证分别记录，不混称真实部署通过。
5. 同步接口契约和部署文档；未执行的服务器构建、远程推送不标记为完成。

## 用户服务器更新步骤

等修复提交推送后，在 `/opt/maple-hush/maple-hush-admin` 拉取并**重新构建前端镜像**。仅 `up` 或 `restart` 不会把源码编进旧镜像；本机桥接构建网络故障未修复前沿用已验证可用的 host 构建网络：

```sh
git pull --ff-only
docker build --network host --progress plain \
  -f frontend/scripts/deploy/Dockerfile \
  -t maple_hush_admin-frontend:local ./frontend
docker compose up -d --no-build --no-deps --wait --wait-timeout 600 frontend
```

确认 `.env` 的 `AUTH_ALLOWED_ORIGINS=http://192.168.100.128` 已生效。关闭仍运行旧前端代码的标签页，再打开 IP 入口验证登录、工作台、首次改密、令牌刷新与退出，避免新旧两种协调代码同时运行。不需要重置数据库密码或后台账号密码，也不需要为此次 HTTP 兼容修复改动 Nginx、数据库容器和后端镜像。
