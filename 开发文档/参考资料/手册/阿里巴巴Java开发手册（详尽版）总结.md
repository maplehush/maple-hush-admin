# 《阿里巴巴 Java 开发手册（详尽版）》总结

> 来源：[本目录 PDF](./阿里巴巴Java开发手册（详尽版）.pdf)。文件标注版本为 **1.4.0，2018 年 5 月 20 日**；PDF 共 42 页，正文采用 1/38 至 38/38 的内部页码。本文按原书七个主题归纳，不是对现有后端项目规范的自动修订。

手册将规则分为“强制、推荐、参考”。这是该手册的约束等级，不等于 Java、Spring 或 MySQL 对所有项目的强制要求。以下保留重要结论和适用边界，不逐条抄录原文。

## 一、编程规约（正文第 1—18 页）

### 命名、常量与代码格式

- 类名用 UpperCamelCase，方法、参数和变量用 lowerCamelCase，常量用全大写下划线；包名用小写，名称应完整、准确，避免拼音与英文混用和含义不明的缩写。
- DTO、VO 等缩写按类型含义使用；POJO 的布尔属性避免以 `is` 开头，以免某些框架的属性解析产生歧义。测试类以被测类名加 `Test` 命名。
- 手册在 SOA 背景下要求对外暴露的 Service/DAO 有接口，内部实现类使用 `Impl` 后缀；示例是 `CacheService` / `CacheServiceImpl`。它**没有要求接口名加 `I` 前缀**。这条不直接决定本模板是否为每个 Service 建接口。
- 不把未经定义的魔法值散落在代码中；常量按作用范围和功能分类，取值集合固定且有业务含义时可考虑枚举，避免一个巨型常量类。
- 使用 4 空格缩进、UTF-8、Unix 换行和必要的空格；一行不超过 120 字符。手册建议方法尽量短、不同逻辑之间留空行，不为视觉对齐堆砌空格。

### 对象、集合、并发与控制语句

- 覆写方法标注 `@Override`；注意包装类型的值比较、空指针和序列化兼容性；DTO、VO 等对象不应随意设置会掩盖缺失输入的默认值。
- 集合转换、`subList`、`Arrays.asList`、遍历中增删元素等操作要理解返回对象的真实行为；比较器应满足自反、对称和传递等排序约束。
- 单例及共享状态要考虑线程安全；线程命名应有业务含义，线程池的线程数、队列和拒绝策略需显式评估；并发更新同一记录要防止丢失更新和锁顺序不一致。
- `if`、循环等控制结构使用大括号；复杂条件抽成可读的变量或方法，外部输入和批量请求应做参数校验。高并发退出条件不宜依赖恰好“等于”某个值。

### 注释（正文第 16—17 页）

- 手册要求类、属性和方法使用 JavaDoc；抽象方法及接口方法应解释功能、参数、返回值、异常和实现注意事项。枚举成员要写明用途。
- 方法内部单行说明放在相关语句上方；注释应传达设计原因和业务含义，代码变更时同步更新。清晰命名能自解释的代码不必重复翻译。
- 手册还将“所有类写创建者和日期”列为强制项，并要求特殊标记注明负责人和时间。是否纳入本项目需要单独决定，不能只因为该手册写了“强制”就覆盖现行规范。

## 二、异常与日志（正文第 19—21 页）

- 先校验可预见的非法输入，不用异常做正常流程控制；捕获异常后要真正处理或继续向上抛出，避免空 `catch`、过大的 `try` 块和在 `finally` 中 `return`。
- 事务中捕获异常时要确认回滚仍会发生；资源释放优先使用 `try-with-resources`。对外 HTTP API 应给出稳定错误码和用户可理解的信息，内部异常保留排查所需上下文。
- 日志使用 SLF4J 门面；低级别日志用占位符避免无谓字符串拼接。错误日志保留现场信息和堆栈，控制生产日志量，避免重复打印。
- 手册给出日志保留至少 15 天等运维要求；实际保留期仍须结合项目合规、存储成本和部署环境确定。

## 三、单元测试（正文第 22—23 页）

- 核心原则是 **AIR**：自动化、相互独立、可重复执行；断言结果由程序判断，测试不依赖执行顺序或人工查看输出。
- 单元测试聚焦方法或类，外部系统交互另由集成测试覆盖。测试代码放 `src/test/java`，测试数据应由测试准备，不假设数据库已有特定记录。
- 用 **BCDE** 检查边界、正常输入、设计约束和错误输入。手册建议的覆盖率数字是历史目标，不能用覆盖率代替对权限、事务和并发风险的实质测试。

## 四、安全规约（正文第 24 页）

- 用户私有数据的访问和修改要做权限校验；敏感数据展示需脱敏。所有请求参数都要验证大小、格式和允许值，尤其是分页大小、排序字段等容易造成资源消耗或注入的输入。
- SQL 值参数使用绑定，不拼接用户输入；向 HTML 输出用户内容时做安全转义。使用 Cookie 的写操作需要考虑 CSRF；短信、下单、支付等消耗资源的操作需要防重放或防刷。
- 对本模板而言，菜单和按钮可见性不能代替后端接口授权，角色分配等高风险操作还要在 Service 复核范围。

## 五、MySQL 数据库（正文第 25—30 页）

- 表名、字段名使用小写且表达业务含义；金额等精确数值用 `decimal`。业务唯一性应以唯一约束或唯一索引兜底，不能只靠“先查再插”。
- 索引与查询一起设计：关联字段类型一致，关注排序、覆盖索引和深分页；使用 `EXPLAIN` 与真实数据验证。手册关于 JOIN 表数、前置通配搜索、分库分表阈值等限制应结合实际查询计划判断。
- 明确列出查询字段；MyBatis 参数值使用 `#{}`，避免将不可信输入直接送入 `${}`。更新只修改需要的字段，并维护更新时间。
- 手册要求固定审计字段名、禁用数据库外键与存储过程等。这些是其数据库治理选择；本模板应在建表设计和迁移评审时明确取舍，不将旧版手册的数据库约定自动套用到现有表设计。

## 六、工程结构（正文第 31—34 页）

- 手册描述开放接口、Web、Service、Manager、DAO 等层的职责与依赖，并区分 DO、DTO、BO、AO、VO、Query 等对象用途。`Manager` 层是可选的复用层，不能据此认定三层后台必须新增该层。
- Maven 坐标和版本应统一管理；线上应用避免依赖未固定的快照版本，升级依赖时检查传递依赖的变化。
- 服务器、JVM 和日志参数应与部署环境匹配；其中一些具体调优值带有 2018 年运行环境背景，应用前应重新测量。

## 七、设计规约（正文第 35—36 页）

- 存储方案、表结构、索引和关键数据结构应在实施前评审并留文档。复杂状态、跨对象调用与协作流程可用状态图、时序图、类图或活动图澄清。
- 设计时覆盖异常流程和边界条件；类保持单一职责，扩展优先考虑组合。接口和抽象用于真实的变化点，而不是给每个单实现类机械配对。
- 必要设计不应被“快速迭代”省略；同时避免为了图纸或抽象本身而增加维护负担。
