# 前端中英文切换实施计划

> 按任务逐项执行。写测试、观察其失败，再实现对应行为；每阶段完成后检查变更，不提交仓库历史，除非用户另行要求。

**目标：** 让 `apps/web-antdv-next` 的简体中文和英文界面保持一致，并支持运行时即时切换。

**方案：** 完善现有 Vben locale 管线与两套应用语言包；将活动产品页面里的硬编码文案改为 locale key；为已知后端菜单增加稳定路径/权限标识翻译映射，对自定义未知菜单保留原始标题。验证语言包结构、菜单映射、页面切换、typecheck 和 build。

**技术栈：** Vue 3、Vben `@vben/locales`、AntdvNext、Day.js、Vitest、现有 Playwright/浏览器冒烟脚本。

**规格：** [前端中英文切换实施方案](./前端中英文切换实施方案.md)

## 全局约束

- 目标应用仅支持 `zh-CN` 与 `en-US`；默认中文、语言偏好持久化。
- 不修改后端接口/菜单数据结构，不翻译用户输入和业务数据，不复活演示页面，不新增第三种语言。
- 使用现有 Vben 页面、表单、表格、通知和 locale 能力；切换时不刷新页面。
- 中英文 locale JSON 结构必须完全一致；未知动态菜单显示接口原值。
- 每次运行验证后记录真实命令和结果；未执行的检查不得标为通过。

## 重点验收风险

1. 页面模块级 schema 若在语言切换前计算一次，会继续显示旧语言；验证已打开页面切换后表格列、表单字段和校验文案同步更新。
2. 服务器动态菜单标题不能仅凭中文文本翻译；验证使用稳定路径/权限键，未知自定义名称不被替换。
3. Vben 公共组件、AntdvNext、Day.js 可能各自使用不同 locale；验证一并切换并覆盖退出确认/语言切换提示。
4. 用户自定义的姓名、部门、备注与字典数据不能被当作静态文案翻译；验证这些值保持原样。
5. 未知持久化 locale 可能令应用组件语言不一致；验证启动时回退到受支持语言并保持应用、AntdvNext 和 Day.js 一致。
