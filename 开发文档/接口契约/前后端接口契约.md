## 1. 通用传输与错误

2026-10-22 补充：请求方法不支持时返回 HTTP 405、`error=BAD_REQUEST` 并携带 Allow 头；框架参数类型转换错误返回 HTTP 400、`INVALID_ARGUMENT`。前端中文显示后端业务消息，英文按稳定 error 编码映射 `errors.json`，未知响应和网络错误显示本地化兜底，登录凭据错误单独处理。

前端 `.env.development` 使用 `VITE_GLOB_API_URL=/api`；[目标应用请求器](../../frontend/apps/web-antdv-next/src/api/request.ts)对普通请求设置 `responseReturn: 'data'`，并用 `code=0` 判定成功。普通成功示例：

```json
{"code":0,"data":{"items":[],"total":0},"error":null,"message":"ok"}
```

本文件下表的“成功 `data`”列给出**每个接口的 JSON `data` 示例**，除 refresh 特例外都放入上述四字段响应壳；`data:null` 表示成功但无正文。失败列引用下表，代表对应 HTTP 状态和完整 JSON 示例。错误码从本项目设计起固定，非声称上游 mock 已实现；T02 建公共错误码，T04 起按任务实现并验证。

| 代号 | HTTP / 业务码 | 完整失败 JSON 示例 | 场景 |
| --- | --- | --- | --- |
| E400 | 400 / 40010 | `{"code":40010,"data":null,"error":"INVALID_ARGUMENT","message":"请求参数无效"}` | 字段格式、数量或缺失 |
| ECAP | 400 / 40011 | `{"code":40011,"data":null,"error":"CAPTCHA_INVALID","message":"验证码无效，请重新获取"}` | 验证码缺失、错误、过期或已使用 |
| EAUTH | 401 / 40100 | `{"code":40100,"data":null,"error":"UNAUTHENTICATED","message":"请重新登录"}` | access/refresh 缺失、失效或账号凭据错误；登录错误不泄露账号是否存在 |
| EFORB | 403 / 40300 | `{"code":40300,"data":null,"error":"FORBIDDEN","message":"没有操作权限"}` | 身份有效但权限不足 |
| ECSRF | 403 / 40301 | `{"code":40301,"data":null,"error":"CSRF_INVALID","message":"请求校验失败，请重试"}` | CSRF 或来源校验失败；前端不得对此触发 refresh |
| ECON | 409 / 40900 | `{"code":40900,"data":null,"error":"CONFLICT","message":"数据已变更或已存在"}` | 名称重复、关联阻止删除或并发冲突 |
| ERATE | 429 / 42900 | `{"code":42900,"data":null,"error":"RATE_LIMITED","message":"操作过于频繁，请稍后再试"}` | 验证码/登录限流 |
| EDEP | 503 / 50300 | `{"code":50300,"data":null,"error":"DEPENDENCY_UNAVAILABLE","message":"服务暂不可用，请稍后重试"}` | Redis 等必需依赖故障 |

受保护请求携带 `Authorization: Bearer <accessToken>`，无身份为 401、已认证但无权为 403。ID 在 JSON 与路径中均为十进制**字符串**，避免 JavaScript 精度损失。管理列表成功结构固定为 `{"items":[...],"total":1}`；Playground [Vxe 表格适配器](../../frontend/playground/src/adapter/vxe-table.ts)读取 `items/total`。所有时间输出为 `Asia/Shanghai` 本地时间的 `yyyy-MM-dd HH:mm:ss`；不会附 `Z`。查询筛选的 `startTime/endTime` 是日期 `YYYY-MM-DD`，后端按东八区整日区间解释，结束日包含全天。前端 [date-range-codec](../../frontend/playground/src/utils/date-range-codec.ts)当前正是这样编码；列表页由前端发送 `page/pageSize`，不发送 `pageNo`。默认 `page=1,pageSize=20`，上限 100。

目标应用 [Vite 开发代理](../../frontend/apps/web-antdv-next/vite.config.ts)目前将 `/api` 重写为空再代理到 `http://localhost:5320/api`，实际 mock 收到的仍是一个 `/api`。T14 切换真实后端时须同步调整代理 target/rewrite，保证对外和后端都只有一个 `/api`，不出现 `/api/api`。生产采用同源 TLS 入口。目标应用现有 `loginApi` 尚未显式 `withCredentials`，同源登录 Cookie 可由浏览器接收；T14 仍须在开发代理和正式入口实测 Cookie 行为。刷新/退出已有 `withCredentials: true`。

正常登录设置 `mh_refresh` Cookie；待改密分支不设置它，也不返回普通 access。refresh 令牌族从首次登录起最长 7 天，轮换不续期，access 默认 15 分钟。生产 refresh Cookie 为 `HttpOnly; Secure; SameSite=Lax; Path=/api/auth`、host-only；`dev` 为本机 HTTP 联调关闭 `Secure`。CSRF Cookie 同样限制 host-only、`Secure`、`SameSite=Lax`、`Path=/api/auth`，且 `HttpOnly`。前端从 `GET /api/auth/csrf` 的 `data.token` 取得提交值，刷新/退出同时送 Cookie 与 `X-XSRF-TOKEN`；登录/退出后重新获取 CSRF 凭据，服务端还校验请求来源。access 已过期仍可用有效 refresh Cookie 与 CSRF 退出；无有效 refresh 时退出幂等清 Cookie。退出、改密或管理员重置后，旧 access 下次请求失效。T05 已落地 Cookie 写接口的 CSRF 与来源校验；T14 合并同页并发 401 并协调多标签页刷新，不能重复提交旧 refresh。

T05 的 CSRF Cookie 名为 `mh_csrf`，JSON `data.token` 为 Spring Security XOR 处理后的提交值；客户端只从 JSON 读取，不能直接把 Cookie 值当请求头。refresh/logout 只接受 `X-XSRF-TOKEN`，不接受查询参数或表单参数替代。登录成功、首次改密成功和退出清除旧 CSRF Cookie；refresh 401 清除两类 Cookie，503 保留原会话以便重试。登录/refresh/logout 校验 `Origin`，缺少时校验 `Referer`；两者均缺少或来源不符返回 ECSRF。`dev` 默认允许 Vben 的 `http://localhost:5999`、`http://127.0.0.1:5999` 及后端本身来源，`test/prod` 必须配置精确的 `AUTH_ALLOWED_ORIGINS`。这里不信任 `Forwarded`/`X-Forwarded-*` 来推断来源；正式同源入口在部署时显式配置。Redis 清理失败不会阻止已经完成数据库撤销的退出。

[UserInfo 类型](../../frontend/packages/types/src/user.ts)继承的 [BasicUserInfo](../../frontend/packages/@core/base/typings/src/basic.d.ts)要求 `userId/realName/avatar/username`；它还保留演示用 `desc/token` 字段，T14 应调整目标应用类型或映射，不能为了满足演示类型再把 token 放进当前用户资料响应。上表加入本项目的 `introduction`。目标应用个人中心 [资料表单](../../frontend/apps/web-antdv-next/src/views/_core/profile/base-setting.vue)当前把 `roles` 作为可编辑的 mock 标签，T16 须改为只读。当前 [改密表单](../../frontend/apps/web-antdv-next/src/views/_core/profile/password-setting.vue)只显示成功提示，T16 对接本人改密 API。现有登录页自动填演示密码并使用 `SliderCaptcha`，T14 改为后端图片验证码。

T06 已落地上表三个 GET 查询接口，普通响应仍使用 `Result`，用户 ID 是字符串，`homePath` 当前为已存在的 `/dashboard/workspace`，不返回演示用 `token/desc` 或 `authVersion`。权限码按字典序去重；路由保留相对子路径，按钮与数据库管理字段不返回，缺省根目录组件为 `BasicLayout`，空子节点省略 `children`。可选用户资料字段允许 `null`，T14 前端须按实际响应处理头像和简介默认值。

唯一超管不得由用户管理接口停用、删除、重置或改角色；前端隐藏入口，后端直接请求同样拒绝。管理员重置别人时自己不退出。`username` 为登录账号，管理页 `name` 映射 `sys_user.real_name`，`remark` 不等于个人资料 `introduction`。

T10 已实现上述七个用户管理接口。详情/分页行的实际 VO 为 `id/username/name/avatar/deptId/roleIds/superAdmin/status/remark/createTime/updateTime`（avatar 为 T13 补充，superAdmin 为 T15 补充），用户、部门、角色 ID 均输出字符串，未分配部门为 null，角色列表稳定按 ID 升序（包括已关联停用角色）。superAdmin 是后端根据内置角色关联计算的只读布尔值，不依赖用户名或固定 ID；仅有 user:list 时也能正确禁用唯一超管的受保护操作，写入 DTO 不接受该字段。分页按用户 ID 升序；`name` 仅筛选真实姓名，不把 username/remark/introduction 混为一谈。Mapper 的管理查询和 VO 不返回密码、哈希、refresh 凭据及授权版本。

- 创建账号和姓名分别非空、至多 64/100 字符；去除首尾空白后保存。账号创建后不可修改。`remark` 至多 500，`deptId` 是现存部门的正整数 ID，表单 null/空白/`"0"` 表示不分配；部门停用不自动停用用户。
- 创建时 status 缺省 1；`roleIds` 可选，省略/null/`[]` 创建无角色账号，仅要求 `system:user:create`；实际分配角色时额外要求 `system:user:assign-role`，角色只接受启用的普通角色。无角色账号首次登录仍须改密，完成后只有基础工作台，不获得管理权限。独立角色全量替换仍允许 `[]` 清空、拒绝 null，最多 100 个正整数 ID，重复 ID 去重；不存在角色或新分配停用角色返回 E400；原已关联停用角色可在角色全量替换时保留，不能新增给其他用户。内置角色/越权返回 EFORB。
- 普通操作者只能管理角色菜单范围不超出本人有效授权的目标用户；拟分配角色的原始菜单集合也必须在此范围，不能通过重置、删除或剥夺高权限普通账号绕过范围校验。超管角色不进入普通授予流程，超管账户身份按角色关联识别。
- 用户更新为资料全量表单：`name` 必填，`deptId` 为空/0 清除部门、`remark` 为空清除原备注，status 省略/null 保留。更新 DTO 不含 username、roleIds、密码、任意头像 URL 或本人 introduction；T13 补充后可传 avatarUploadId 绑定本人上传的公开图片；创建/更新/角色表单未知字段返回 E400，不能把敏感字段被忽略当作修改成功。
- 停用账号的启用会恢复既有角色能力，除 update 外还须 assign-role 并校验目标当前角色范围。既有停用角色可保留，不因此赋予停用角色权限。
- 资料修改只清快照并保留会话；状态发生变化、角色实际变化和密码重置均递增 authVersion、撤销目标 refresh 会话并在提交后清快照。同一角色集合重提为幂等，不额外踢出。重置仅影响目标用户（本人重置自己也失效）；唯一超管拒绝停用、删除、重置及任何角色变更，允许正常姓名/部门/备注编辑。
- 删除在同一事务中先使目标会话失效，清理 refresh 行和角色关联，再删用户；登录和操作审计快照保留。新建/重置只存 `12345678` 的 BCrypt 哈希，响应不含临时密码，待改密登录只返回专用短期凭据。个人中心本人旧密码/新密码改密仍由 T13 实现。
- 分页 page 从 1 开始、pageSize 为 1～100；姓名至多 100、deptId 筛选为正整数、状态 0/1、日期为有效 YYYY-MM-DD。开始/结束日均按东八区整日闭区间查询，反向/无效日期返回 E400。目标不存在返回 404、唯一账号/外键关联冲突返回 ECON。

`permissions` 是菜单节点 ID 数组，不是权限码字符串。`super_admin` 内置角色不能走普通角色修改、删除或授予流程。角色授权需包含可用目录祖先与按钮所属页面，并在 Service 校验操作者可授予范围。

`roleCode` 创建必填、创建后不可变（改码返回 ECON），只接受小写字母开头、字母/数字/下划线且至多 64；`name` 非空至多 100，`remark` 至多 500。状态创建缺省 1、修改省略/null 则保留原状态；权限创建缺省空集合、修改省略/null 则保留，`[]` 明确清空。权限输入最多 100 个正整数 ID，祖先自动补齐；新孤立按钮/未知节点/错误字段返回 E400。取消原页面时回传的原按钮同步清理。

普通新增/修改需各自接口码，实际改变权限或把停用角色启用还需 `system:role:grant`，并校验本人有效授权范围；内置角色写入/重建返回 EFORB，重复编码返回 ECON，不存在角色返回 HTTP 404。权限/状态变化和删除影响所有原持有者，旧 access/refresh 失效，重新登录；无授权变化的名称/备注修改保留会话。T15 表单须区分属性编辑、权限编辑和启用所需权限，不把隐藏按钮当作安全校验。

### T11 字典接口实施细节

T11 已实现表中 11 个字典接口（含补充的字典项详情）；两个日志分页接口已由 T12 实现。现有 V2 已包含 `SystemDict` 页面节点和 `system:dict:list/create/update/delete`，本轮不新增重复节点或迁移。管理接口使用对应权限码；`GET /api/system/dict/type/{dictCode}/items` 仅要求已登录，不要求字典管理权限。

- 类型 VO 为 `id/dictCode/name/status/remark/createTime/updateTime`；字典项 VO 为 `id/dictTypeId/label/value/color/sort/defaultItem/status/remark/createTime/updateTime`。ID 为字符串，时间为东八区秒级；普通选项只有 `label/value/color/defaultItem`，不含管理备注。
- 类型 `dictCode` 创建必填，限定小写字母开头、字母/数字/下划线、至多 100 字符，创建后不可改；更新可省略或回传原值，变码返回 ECON。`name` 非空至多 100，映射 dict_name。
- 字典项 `dictTypeId` 必须是现存类型的正整数 ID；更新必须回传原类型，跨类型移动返回 ECON。`label/value` 非空至多 200，去除首尾空白，同类型 value 唯一、不同类型允许同值，数据库唯一约束兜底返回 ECON。
- `remark` 至多 500，空值清除。颜色只接受 null、空字符串或 `#RRGGBB`，HEX 大小写均接受并转小写保存；空值清除旧颜色，未知字段拒绝。颜色和 defaultItem 均不自动启停字典项。
- status 创建缺省 1、更新省略/null 保留；sort 创建缺省 0、更新省略/null 保留，接受有符号整数；defaultItem 创建缺省 false、更新省略/null 保留。设置 true 在所属类型行锁下清旧置新，发生重复值等错误时整体回滚；同类型包含停用项在内至多一个默认项。删除默认项后允许没有默认项，不自动选择其他项。
- 类型/项列表均返回 `items/total`，page 从 1 开始、pageSize 为 1～100。类型支持 dictCode/name 包含筛选、0/1 状态；字典项必须提供 dictTypeId，可按 label 包含及状态筛选。管理查询包含停用数据。
- 仅支持 `sortBy` 和 `sortOrder=asc|desc`：类型排序键为 `id/dictCode/name/createTime`，默认 id；项排序键为 `sort/id/label/value/createTime`，默认 sort。默认升序，非 ID 排序追加 ID 升序保证分页稳定；无效键或方向返回 E400，列名由后端 Lambda 映射。
- 普通编码查询只返回启用类型下的启用项，按 sort/id 升序。停用类型返回 `[]`；不存在类型/项返回 404。默认项若被停用，不会在普通结果中出现，也不会自动指定其他默认项。
- 类型包含任何项（包括停用项）时删除返回 ECON，须先显式删除关联项；字典项删除不删除类型。六个写操作使用已有字典 create/update/delete 操作码，审计目标类型区分 dict_type/dict_item，成功和失败均沿用独立审计事务。
- 字典变更不改变用户/角色权限，不递增 authVersion，不踢出当前用户；本轮不增加字典缓存，提交后的查询直接读取 MySQL。类型/项更新采用全量文本资料，前端切换状态或默认项时也须携带必填表单字段。
- T15 字典管理列表使用状态开关时，先读取对应类型/项详情，再将完整更新 DTO 与目标 `status` 发往现有 PUT 接口；不以列表缓存构造更新请求，也不新增状态专用接口。切换前确认，取消不提交。

| startTime/endTime | 支持 | 支持 | 东八区 yyyy-MM-dd 或 yyyy-MM-dd HH:mm:ss，必须为真实日期 |

时间范围起始包含、结束日期包含全天、结束时刻包含该秒；内部转换为左闭右开区间。日期和时刻可混用；同一时刻可查该一秒，反向范围拒绝。空白文本筛选视为未筛选；显式空时间、未知参数、非法分页和排序返回 `INVALID_ARGUMENT`，不将筛选文本拼入 SQL。前端完整时刻需要正常 URL 编码空格。

- 操作 VO：`id/actorUserId/actorUsername/operationCode/targetType/targetId/success/summary/requestMethod/requestPath/clientIp/traceId/createTime`。actorUserId 可空，ID 均为字符串；summary 始终为“操作成功”/“操作失败”，不直接返回历史任意摘要，写入边界也强制此规则。requestPath 记录实际请求路径，包含路径实参，不包含查询串、请求体或请求头；历史记录可能仍是带 {id} 占位符的路由模板，不回写历史数据。

### T13 本人资料、改密与头像实施细节

三个接口均仅依赖普通 access 登录身份，不要求系统管理权限；待改密凭据、失效 access 和匿名请求均返回 401。用户 ID 从认证上下文取得，无法通过表单修改他人资料。用户角色和账号只读。

| 接口 | 表单与结果 | 约束 |
| --- | --- | --- |
| PUT /api/user/profile | realName/introduction → userId/realName/introduction | realName 必填、非空白、最多 100；introduction 最多 500，省略/null/空白清除；文本去除首尾空白 |
| PUT /api/user/password | oldPassword/newPassword → null | 旧密码错误返回 400 INVALID_ARGUMENT；成功递增 authVersion、撤销本人全部 refresh、清快照、清 refresh/CSRF Cookie，不签发新 token |
| POST /api/user/avatar | multipart 单个 file → avatar | 不接受任何其他文件或普通字段，文件名/客户端 MIME 不决定内容和对象路径 |

资料/改密 JSON 未知字段返回 400，拒绝 userId/username/roles/deptId/status/remark/avatar 等额外字段。本人简介不覆盖管理员备注。资料和头像修改保留现有会话；更新后删除 Redis 快照，读取时也比对 MySQL 姓名/头像/简介/账号，旧快照回填或删除失败不能恢复旧资料。

新旧密码不做 trim；新密码至少 8 字符、最多 128 字符且 UTF-8 不超过 BCrypt 的 72 字节上限，拒绝旧密码和常见密码；共用 PasswordPolicy，首次改密也遵守此限制。每个用户每 5 分钟最多 5 次进入改密 Service 的尝试，超限返回 429；Bean Validation 提前拒绝的畸形表单不计入此计数。Redis 不可用返回 503，不绕过限流。改密成功后前端在 T16 丢弃当前 access 并跳登录页，用户直接使用新密码登录，无临时密码或再次强制改密流程；其他用户会话不受影响。

头像原始文件最大 2 MiB，multipart 超限返回 HTTP 413、业务码 INVALID_ARGUMENT；其他空文件/损坏/伪装格式/非法尺寸返回 400。支持真实 JPEG、PNG、WebP，解码首帧、移除元数据后统一重新编码 PNG；宽高各不超过 4096、总像素不超过 1600 万，重新编码后的 PNG 也不能超过 2 MiB。服务端生成 `vben-admin-img/{本人ID}/{32位随机UUID}.png`，忽略原始文件名，响应为受控公开 HTTPS URL，数据库保存该长期 URL。

OSS SDK 在后端使用、延迟创建客户端，缺少凭据仅使头像上传返回 503，不影响资料/登录等其他功能。地域兼容 OSS_REGION=oss-cn-beijing（SDK 自动规范化 cn-beijing）；凭据通过 OSS_ACCESS_KEY_ID/OSS_ACCESS_KEY_SECRET 与可选 OSS_SECURITY_TOKEN 注入。上传前读取 Bucket ACL，仅接受 public-read，不替用户修改 ACL 或开放匿名写；需要 GetBucketAcl、受控前缀 PutObject/DeleteObject 权限。

头像上传先完成对象写入，再在短数据库事务锁定本人并复核状态/版本；身份变化拒绝 401 并清新对象，数据库失败返回安全 500 并清新对象，成功提交后清旧对象。PUT 超时可能已落地时也尝试删除新对象。只删除精确受控域名/前缀/本人 ID 目录/32位小写随机名下的 PNG；带签名参数、片段、转义、其他域名或其他用户 URL 不删除，旧格式由人工迁移处理。删除失败不改变已提交结果，安全日志记录随机 Object Key 与进程内计数供运维重试，不记录原始 SDK 异常/密钥。本人三种写操作沿用独立操作审计，操作码为 user:profile:update、user:password:update、user:avatar:update，不作为可分配管理权限码。

用户指定实际 OSS 上传由本人后续测试；本轮自动验证使用外部存储/SDK 测试替身，未声明真实 OSS 连接、ACL 或匿名读写已经通过。前端页面和跳转在 T16 实施。

### T13 补充：统一文件上传与用户头像绑定

2026-10-22 补充：统一上传与本人头像共享账户上传配额，默认每分钟 10 次、每 24 小时 100 次，分别由 `FILE_UPLOAD_PER_MINUTE`、`FILE_UPLOAD_PER_DAY` 配置为正整数。两个窗口从首次预占起计时；已预占后发生的失败也计入次数，达到限制返回 HTTP 429 / `RATE_LIMITED`，Redis 故障返回 HTTP 503 / `DEPENDENCY_UNAVAILABLE`，不继续写入 OSS。配额不改变公开素材、上传凭据和头像绑定规则。

`POST /api/files/upload` 为统一文件入口，包位置 `system/file`；首版白名单为 JPEG/PNG/WebP 公开图片，最大 2 MiB、实际解码/净化 PNG 和尺寸限制与本人头像接口一致。其他文件格式拒绝 400；未来按业务需要扩展类型、大小、公开/私有访问策略，不把办公附件默认上传到公共读头像 Bucket。当前不新增文件管理页面、附件表或任意路径上传接口。

- 认证：普通 access 登录即可；匿名/失效 token 返回 401。只接受 multipart 中一个 `file`，路径、用户 ID、类型和其他额外字段拒绝 400，超限 413。客户端 MIME/扩展名不决定服务端格式，原文件名只取基础名、移除控制字符后作为显示信息，最大 255 字符。
- 成功 `data`：`{"uploadId":"32位随机小写十六进制","name":"photo.jpg","url":"https://maple-hush.oss-cn-beijing.aliyuncs.com/vben-admin-img/files/1/随机名.png","contentType":"image/png","size":1234}`。size 为净化后对象的字节数，url 是长期公开地址；uploadId 是绑定凭据，有效 2 小时、属于当前上传人，不是数据库文件主键。
- 对象路径由服务端固定为 `{OSS_OBJECT_PREFIX}files/{上传人ID}/{随机UUID}.png`，不改变当前用户头像。上传后 Redis 保存 `{key-prefix}:file_upload:{uploadId}` 的上传人和 URL；凭据保存失败返回 503 并补偿刚上传的新对象，补偿失败仅记录安全对象键，不泄露 Redis/SDK 异常消息。
- 创建/修改用户的原接口增加可选 `avatarUploadId`，仅接受 32 位小写十六进制，不接收任意 avatar/avatarUrl。Service 沿用原管理权限、范围检查和数据库事务，读取上传凭据验证归属：未知/过期返回 400、他人凭据 403、Redis 不可用 503；失败不留下部分用户变更。上传凭据不消费，支持有效期内表单失败重试与同一上传人素材复用。
- 新增时省略/null 为无头像；修改时省略/null 保留原头像。用户列表/详情增加可空 `avatar`，来自 avatar_url，不输出上传标识；上传后尚未提交的标识保存在前端表单内，编辑已有头像未重新上传时省略 avatarUploadId。绑定头像不改变目标角色或会话，提交后清目标资料快照。
- `POST /api/user/avatar` 继续专用于当前登录人的立即上传/绑定，复用共享图片校验，原有个人中心失败补偿和清理规则不变；统一文件上传成功仅表示素材已交付，不代表业务表单已提交。

通用素材是长期可复用的公开资源，凭据过期、取消表单、绑定失败或某用户替换头像均不自动删除，避免误删其他业务引用；个人中心删除旧头像的归属规则不会删除 `files/` 通用目录。首版没有通用文件删除或引用管理，未使用素材清理需后续引入引用策略；**不能直接给 files/ 配置到期删除生命周期**，否则会删除已绑定头像。若后续需要私有附件，应先扩展存储访问策略与相应业务授权。

T15 的用户新增/编辑流程：先调用统一上传，预览返回 url，再以 avatarUploadId 提交用户表单；已有头像显示用户 VO 的 avatar。T16 的个人中心可继续使用本人头像入口。

### T14 前端落地（2026-10-15）

**2026-10-27 会话兼容更新**：下文 Web Locks 为早期实现，当前已用 IndexedDB readwrite 事务替代跨标签页协调，不再调用 `navigator.locks` 或 `crypto.randomUUID()`。会话代次使用 `crypto.getRandomValues`；同页仍通过 pending Promise 合并刷新。同源共享状态键和后端单次轮换/重放撤销契约不变。等待协调失败且尚未提交刷新时保留会话，不使另一页面的正常刷新失效；浏览器拒绝存储或前端处理异常单独提示，不误报凭据错误。HTTP dev 可登录和续期，test/prod 仍使用 HTTPS 与 Secure Cookie。实现和验证见 [HTTP 登录兼容修复](../2026-10-27-HTTP登录兼容修复.md)。

目标应用 API 固定同源 /api；认证 fetch 独立于业务 Axios 拦截器。登录严格区分 passwordChangeRequired 两个分支，待改密 token 只在内存，改密成功回登录。登录/退出后主动 GET csrf；每次 refresh/logout 前重新 GET csrf，不依赖 Cookie 文本或长期缓存的 token。业务 401 仅刷新/重试一次，403 从不刷新；刷新 503 保留会话，不确定网络失败/CSRF403/协调失败要求重登。

共享浏览器状态键为 maple-hush-admin:auth:v1，仅含 epoch/revision/短期 access。Web Locks 同源互斥认证 Cookie 操作，BroadcastChannel/storage 分发状态；不保存 refresh/密码/首次改密 token。获锁后核对请求 epoch；旧账号的 401 或排队退出不操作新账号。登录后续 CSRF 获取失败会清旧身份；共享写失败清会话，不带旧身份继续使用已更换的 Cookie。缺少持久化平台标记时不继承官方 demo 登录态。

/user/info 的 avatar/introduction 可空，前端头像为空时使用默认头像，简介映射空文本；不虚构 token/desc。`/api/menu/all` 返回角色授权路由，并固定附带已登录用户共用的“概览 / 工作台”基础入口；基础入口不授予业务权限码，也不作为角色菜单授权项。个人中心与 403 保持前端受保护基础路由。未授权 `/system` 路径显示 403，服务端仍独立授权。页面 URL 为 `/system/user` 等，component 为 `/system/user/list` 等；七个组件已由 T15 接真实交互。清身份后重建基础路由，删除上一账号动态路由。首次改密返回时 Login 的 KeepAlive 激活钩子重新领验证码并清密码。

后端时间是东八区墙钟文本，parseServerDateTime 按 YYYY-MM-DD HH:mm:ss 严格解析供表单原样显示；上海/纽约时区 DatePicker 已实际核对，不对该文本再加八小时。日期范围过滤仍由后端按东八区解释。
