# 后端分层重构记录

日期：2026-10-14。来源：T09 完成后，用户明确要求采用 JeecgBoot 风格的 Service 接口、实现类命名及分包，并整理认证模块根包。此调整不启动 T10，不增加业务接口或数据库迁移。

## 统一规则

- 业务仍为 Controller → Service → Mapper 三层。Service 接口放功能包 `service/`，名称以 `I` 开头；实现放 `service/impl/`，以 `Impl` 结尾，即使只有一个实现也成对建立。
- Controller、其他 Service、过滤器与切面等调用方依赖业务接口。`@Service`、事务和操作审计注解保留在实现类，接口只暴露已有业务能力。
- 本次不默认继承 MyBatis-Plus `IService` / `ServiceImpl`；已有写操作需要授权、校验、版本失效和审计，不能旁路开放通用 CRUD。
- 同业务模块的接口留在 `admin-system-biz`。`admin-system-api` 仍只按真实跨模块消费者建立只读契约。

菜单模块示例：

```text
menu/
├─ controller/SysMenuController.java  # 注入 ISysMenuService
├─ service/ISysMenuService.java
├─ service/impl/SysMenuServiceImpl.java
├─ mapper/SysMenuMapper.java
├─ dto/SysMenuSaveDTO.java
├─ vo/SysMenuVO.java
├─ entity/SysMenu.java
└─ support/...
```

## 已迁移的业务服务

下表路径以 `admin-system-biz/src/main/java/com/maplehush/admin/system/` 为根。每个接口对应同功能 `service/impl/` 下的实现。

| 功能 | 接口 | 实现类 |
| --- | --- | --- |
| 认证 | `auth/service/IAuthService` | `AuthServiceImpl` |
| 会话 | `auth/service/IAuthSessionService` | `AuthSessionServiceImpl` |
| 验证码、限流、Redis 快照 | `auth/service/IAuthRedisService` | `AuthRedisServiceImpl` |
| 当前用户快照 | `auth/service/IUserSnapshotService` | `UserSnapshotServiceImpl` |
| 有效权限 | `permission/service/IPermissionService` | `PermissionServiceImpl` |
| 授权版本失效 | `permission/service/IAuthorizationChangeService` | `AuthorizationChangeServiceImpl` |
| 菜单 | `menu/service/ISysMenuService` | `SysMenuServiceImpl` |
| 部门 | `dept/service/ISysDeptService` | `SysDeptServiceImpl` |
| 角色 | `role/service/ISysRoleService` | `SysRoleServiceImpl` |
| 登录审计（原 `auth/LoginAudit`） | `log/service/ISysLoginLogService` | `SysLoginLogServiceImpl` |
| 操作审计 | `log/service/ISysOperationLogService` | `SysOperationLogServiceImpl` |

认证模块同步整理：

- `AuthController`、`AuthSessionController` 移至 `auth/controller/`；登录和首次改密表单分别提取为 `auth/dto/LoginDTO`、`InitialPasswordDTO`，JSON 字段与校验不变。
- 安全链配置放 `auth/config/`；过滤器、Cookie 和来源策略放 `auth/security/`；令牌组件放 `auth/security/token/`。
- `BootstrapGuard` 放 `auth/bootstrap/`，会话清理放 `auth/schedule/`，密码规则与摘要工具放 `auth/support/`。
- 权限图组装放 `permission/support/`，权限异常处理放 `permission/handler/`。基础组件按职责分包，不额外包装业务接口。
- Service 的内部结果 record 随接口归属，调用方不再引用实现类。用户最小快照的私有序列化结构仍留实现内部。

## 实际验证

本机环境：Java 21、MySQL 8.0.24、Redis 3.0.504。数据库、Redis 开发凭据使用已批准默认值；未进行 Docker 或目标 MySQL 8.4 验证。

在 `backend/` 执行：

```powershell
$env:T04_IT_ENABLED='true'
$env:T05_IT_ENABLED='true'
$env:T06_IT_ENABLED='true'
$env:T07_IT_ENABLED='true'
$env:T08_IT_ENABLED='true'
$env:T09_IT_ENABLED='true'
$env:MYSQL_DATABASE='maple_hush_admin'
.\mvnw.cmd -ntp clean verify
```

结果：五个 reactor 项均 `SUCCESS`；25 个单元测试、43 个真实 MySQL/Redis 集成测试通过，无失败或错误。未启用 T03 专项开关，`SystemMigrationIT` 的 3 个迁移/升级测试按原配置跳过。覆盖认证、改密、会话轮换/退出、权限、菜单/部门/角色管理以及独立事务审计；清理旧 class 后重新编译，避免原包残留掩盖引用问题。

补充指定 JDK 接口代理配置的专项回归（启用 T06/T07/T09 开关）：

```powershell
.\mvnw.cmd -ntp verify '-Dit.test=PermissionFlowIT,MenuManagementIT,RoleManagementIT' '-Dfailsafe.failIfNoSpecifiedTests=false' '-Dspring.aop.proxy-target-class=false'
```

结果：25 个单元测试及 24 个专项集成测试通过，所有 reactor 项 `SUCCESS`；检查权限拒绝、授权版本失效、角色/菜单写入事务、成功/失败独立审计、外层事务回滚审计及缓存失效故障降级。

独立静态审查逐一核对 11 组业务服务、迁包引用、SQL、事务与审计注解、DTO 校验及旧 Bean 名依赖，未发现需要修复的重构缺陷。审查者未修改代码或运行测试。
