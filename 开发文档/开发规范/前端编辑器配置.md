# 前端编辑器配置

## 配置位置

VS Code 使用当前打开目录下的 `.vscode`，不会自动加载普通子目录中的配置。

| 打开的目录 | 配置位置 | ESLint 工作目录 | Oxc 配置路径前缀 |
| --- | --- | --- | --- |
| `frontend` | `frontend/.vscode` | `.` | 无 |
| `maple-hush-admin` | `.vscode` | `./frontend` | `frontend/` |
| 本机搭建目录 `maple-hush-workspace` | 外层 `.vscode` | `./maple-hush-admin/frontend` | `maple-hush-admin/frontend/` |

以 `frontend/.vscode` 为基础维护设置、扩展推荐、代码片段和调试入口。同步到其他层级时，调整 ESLint 工作目录、Oxc 配置、TypeScript SDK、Tailwind 配置、CSS 变量、国际化目录及调试 `webRoot` 的相对路径。外层配置通过明确的语言设置指定前端格式化器，避免将 Oxc 设为 Java 等其他语言的默认格式化器。

仓库根与 `frontend` 下的四个共享文件由 Git 管理：`settings.json`、`extensions.json`、`launch.json`、`global.code-snippets`。其他 `.vscode` 文件继续忽略。搭建目录的配置在产品仓库之外，不属于产品提交内容。

## 编辑器扩展与保存

- 安装扩展推荐中的 `oxc.oxc-vscode` 和 `dbaeumer.vscode-eslint`；Vue 开发使用 `Vue.volar`。
- Oxc 按 `oxfmt.config.ts` 格式化；ESLint 按 `eslint.config.mjs` 修复导入排序等规则。单独运行“格式化文档”不执行 ESLint 修复。
- 配置已开启保存格式化与 `source.fixAll.eslint`。使用 `Ctrl+S` 手动保存以同时触发修复；自动保存不作为触发 ESLint 修复的保证。
- 安装扩展或修改工作区配置后，可执行 `Developer: Reload Window` 重新加载窗口。

调试配置仅保留目标应用 `http://localhost:5999`，需先在 `frontend` 执行 `pnpm dev:antdv-next`。官方文档站与 Playground 已移除，三份配置同步去掉对应调试入口和语言目录。

## 命令行检查

在 `frontend` 目录执行：

```powershell
pnpm exec eslint apps/web-antdv-next/src --quiet
pnpm exec oxfmt --check apps/web-antdv-next/src
pnpm --filter @vben/web-antdv-next typecheck
```

需要批量修复时运行 ESLint 的 `--fix` 与 Oxfmt 的 `--write`，随后重新检查并查看差异。
