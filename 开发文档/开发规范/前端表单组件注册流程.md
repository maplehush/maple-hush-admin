# web-antdv-next 表单组件注册流程

适用应用：`frontend/apps/web-antdv-next`。以 AntdvNext 的 `ColorPicker` 为例，说明如何让 UI 组件通过 `useVbenForm` 的 schema 使用。组件注册在应用适配层完成；字段格式、限制和校验由业务页面配置。

## 1. 先确认组件接口

查看当前安装版本的组件类型与实现，确认导出路径、Props、绑定属性、更新事件、返回值和清空行为。不要只根据其他 UI 库的同名组件推断。

本项目 `ColorPicker` 的入口为 `antdv-next/dist/color-picker/index`，Props 为 `ColorPickerProps`，双向绑定为 `value` / `update:value`。默认更新值可能是颜色对象，`valueFormat` 可指定输出字符串；清除颜色需要同时考虑颜色对象的 `cleared` 状态。

## 2. 导入类型并异步加载组件

编辑 [`src/adapter/component/index.ts`](../../frontend/apps/web-antdv-next/src/adapter/component/index.ts)：

```ts
import type { ColorPickerProps } from 'antdv-next';

const ColorPicker = defineAsyncComponent(
  () => import('antdv-next/dist/color-picker/index'),
);
```

沿用该文件已有的异步加载方式。组件确有额外转换需求时再增加包装；支持标准绑定协议的组件可以直接注册。

## 3. 补全名称、Props 类型与运行时注册

在同一个文件中同步补充三处：

```ts
// ComponentType 联合类型中增加：
| 'ColorPicker'

// ComponentPropsMap 接口中增加：
ColorPicker: ColorPickerProps;

// initComponentAdapter() 的 components 对象中增加：
ColorPicker,
```

`ComponentType` 提供合法组件名称，`ComponentPropsMap` 提供 schema 的属性类型提示，`components` 提供运行时组件。三者必须使用相同名称。`globalShareState.setComponents(components)` 会统一完成注册，无需逐个调用 Vue 的全局组件注册。

## 4. 核对表单双向绑定

[`src/adapter/form.ts`](../../frontend/apps/web-antdv-next/src/adapter/form.ts) 的 `baseModelPropName` 已配置为 `value`，因此 `ColorPicker` 无需再配置映射。

其他组件若采用不同属性，应在 `modelPropNameMap` 中声明，例如 `Switch: 'checked'`、`Upload: 'modelValue'`。单个字段也可用 schema 的 `modelPropName` 覆盖。确认对应事件分别为 `update:checked`、`update:modelValue` 等；仅修改绑定属性名不能转换组件返回值。

[`src/bootstrap.ts`](../../frontend/apps/web-antdv-next/src/bootstrap.ts) 已依次调用 `initComponentAdapter()` 和 `initSetupVbenForm()`。新增组件沿用这条启动链，不需要额外初始化。

## 5. 页面通过 schema 使用

页面从 `#/adapter/form` 导入 `useVbenForm` 或 `VbenFormSchema`，以字符串名称选择注册组件。字典颜色字段的配置位于 [`dict/data.ts`](../../frontend/apps/web-antdv-next/src/views/system/dict/data.ts)：

```ts
import type { Color } from 'antdv-next/dist/color-picker';

{
  component: 'ColorPicker',
  fieldName: 'color',
  componentProps: {
    mode: 'single',
    format: 'hex',
    disabledFormat: true,
    disabledAlpha: true,
    allowClear: true,
    presets: [
      {
        label: $t('system.dict.commonColors'),
        defaultOpen: true,
        colors: ['#F5222D', '#FA541C', '#FA8C16', '#FAAD14', '#52C41A', '#13C2C2', '#1677FF', '#722ED1', '#EB2F96', '#000000', '#8C8C8C', '#D9D9D9', '#FFFFFF'],
      },
    ],
    showText: true,
    valueFormat: (color: Color) =>
      color.cleared ? '' : color.toHexString(),
  },
}
```

`format` 控制面板显示格式，`valueFormat` 控制绑定值格式。字典颜色只允许六位 HEX，故关闭透明度和渐变；预设颜色通过 `presets` 配置并默认展开；清除输出空串，提交时由 `dictItemPayload()` 转换为 `null`。这些业务限制放在字典 schema 中，适配器注册的 `ColorPicker` 仍可供其他页面配置 RGB、透明度或其他模式。

校验规则继续写在 schema 的 `rules` 中，字段标签、帮助和错误文案通过 `#/locales` 获取。无需再为该字段编写原生 input 或自定义插槽。

## 6. 验证

在 `frontend/` 下执行目标应用检查：

```sh
pnpm --filter @vben/web-antdv-next typecheck
pnpm --filter @vben/web-antdv-next build
```

实际使用时检查：新增初始空值、已有值回显、选择颜色、手动编辑色值、清除、重置，以及提交的数据格式。遇到浮层遮挡时，核对组件的弹出容器与抽屉层级配置。

参考：[Vben 表单文档](https://doc.vben.pro/components/common-ui/vben-form.html)。具体接口以当前依赖版本源码为准。
