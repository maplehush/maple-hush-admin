# 后端开发规范

本规范供仓库 `backend/` 工程使用；T02 已落地四模块公共底座，业务代码按后续任务实施。系统范围、技术选型及 Vben API 契约见[总体架构](../架构设计/总体架构.md)，模块职责和目录见[后端项目结构](../架构设计/后端项目结构.md)。本文件位于仓库 `开发文档/开发规范/`；架构和任务文档按[总流程](../任务拆解/项目搭建与Docker一键部署执行流程.md#0-交付目标与边界)分类维护。

《阿里巴巴 Java 开发手册》是参考材料，其中“强制、推荐、参考”表示原手册的分级，不自动覆盖本项目约定。本项目保持模块化单体和 Controller → Service → Mapper 三层；单实现 Service 不强制配接口或 `Impl`，实体不加 `DO`、`Entity` 后缀，不要求类注释记录作者和创建日期，也不以固定覆盖率、JOIN 数量或禁用外键作为统一门槛。采用或调整规则时，以本规范和架构设计中的明确决定为准。

## 命名与目录

| 对象 | 约定 |
| --- | --- |
| Maven 与包 | Maven 模块名用小写连字符；`groupId=com.maplehush`；Java 包前缀 `com.maplehush.admin`，包名全小写，业务按功能分包 |
| 系统管理类 | 类名以 `Sys` 开头，例如 `SysUserController`、`SysUserService`、`SysUserMapper`；部门统一用 `Dept` |
| 表实体 | 放功能包的 `entity/`，类名不加 `Entity` 后缀，例如 `SysUser`、`SysDept`；不直接作为 HTTP 入参或出参 |
| 时间基类 | `admin-base-core/common/entity/BaseEntity` 为抽象类，仅声明 `LocalDateTime createTime`、`updateTime`；仅有对应两列的实体继承，`id` 留在具体实体 |
| 输入和跨模块数据 | 输入放 `dto/`，类名以 `DTO` 结尾，例如 `LoginDTO`、`SysUserSaveDTO`；不叠加 `Request` 后缀。跨模块传输对象也用 `DTO` |
| HTTP 输出 | 放 `vo/`，类名以 `VO` 结尾，例如 `CurrentUserVO`；跨模块契约不复用 HTTP VO |
| 业务服务 | 单实现类直接放功能包的 `service/`，例如 `SysDictService`；不强制配接口或 `impl/` 目录。有真实多实现或跨模块边界时再定义接口，以职责命名，不加 `I` 前缀 |
| 其他 Java 类型 | Controller 用 `...Controller`，Mapper 用 `...Mapper`，配置类用 `...Configuration`；测试类用 `...Test` 或 `...IT` |
| 标识符 | 方法名用动词短语，字段用 lowerCamelCase，常量用 `UPPER_SNAKE_CASE`；表名用 snake_case；权限码全小写 |
| 时间列 | 数据库时间点列统一用 `_time` 后缀，例如 `create_time`、`update_time`、`expire_time`、`used_time`、`revoked_time`；Java 属性相应使用 `createTime` 等 lowerCamelCase 名称 |
| 排序值 | 部门、菜单、字典项统一用 `sort` 列和 Java `sort` 属性；数字越小越靠前，同值按 `id` 升序，不要求 `sort` 唯一 |
| 布尔属性 | Java POJO 属性名不以 `is` 开头；数据库列允许使用 `is_` 前缀，但实体必须显式映射。例如 `SysRole.builtIn` 对应 `is_builtin`，`SysDictItem.defaultItem` 对应 `is_default` |

认证和当前用户类使用 `Auth...`、`CurrentUser...`，与系统管理类区分。`Result<T>` 和 `PageResult<T>` 是公共响应容器，不按业务 VO 命名。

上述两个实体字段使用 `Boolean builtIn`、`Boolean defaultItem`，分别声明 `@TableField("is_builtin")`、`@TableField("is_default")`；DTO/VO 如需暴露这些含义，也使用不以 `is` 开头的 Java 属性名。不要写 `Boolean isBuiltin` 或 `Boolean isDefault`，避免 JavaBean 属性解析与序列化结果不一致。

Service 和 Mapper 方法按返回目的选动词：单条查询用 `get`，列表用 `list`，计数用 `count`，创建用 `save`，修改用 `update`，删除用 `remove`；方法名还应写明业务对象和条件，避免只有 `handle`、`process` 等空泛名称。共享常量按所属功能放在对应模块的 `constant/`，仅真正跨模块通用的常量进入 `admin-base-core`；权限码留在业务模块，不建立全项目巨型常量类。

## 分层与依赖

- 业务代码按功能分包，包内遵循 Controller → Service → Mapper。Controller 处理 HTTP、校验、权限声明和 DTO/VO 转换；Service 处理业务规则、授权范围和事务；Mapper 负责 SQL 与映射。
- 同模块调用所需 Service；只有真实抽象边界才定义接口，不为了分层形式而复制一套接口/实现文件。跨模块 Java 契约放 `*-api`，由对应 `*-biz` 实现；业务模块不得直接访问别的模块的 Mapper、表实体。
- `*-api` 不放 Controller、Mapper、表实体，也不自动继承 MyBatis-Plus 的通用 CRUD 接口。规则校验器、转换器等辅助类按功能放 `support/`。
- 单表的条件查询、分页和简单条件更新优先使用 MyBatis-Plus 的 `LambdaQueryWrapper<SysUser>`、`LambdaUpdateWrapper<SysUser>` 等类型安全构造器；实体类型按实际表使用 `SysUser`、`SysRole` 等。Wrapper 只在 Service/Mapper 范围内构造，不从 Controller 接收前端传来的 SQL 片段或 Wrapper。跨表授权查询、复杂统计、锁定与并发控制等使用明确的 Mapper SQL，并核对查询计划。更新必须限定目标行，校验受影响行数；Wrapper-only 更新须明确设置 `update_time`，不能假设实体自动填充会生效。
- `BaseEntity.createTime` 使用 `@TableField(fill = FieldFill.INSERT)`，`updateTime` 使用 `@TableField(fill = FieldFill.INSERT_UPDATE)`；由 `TimestampMetaObjectHandler` 产生东八区秒级值，已有值时不覆盖调用方显式赋值。Wrapper-only 更新和自写 SQL 不依赖自动填充，须明确更新 `update_time` 的方式，并与数据库 `ON UPDATE CURRENT_TIMESTAMP` 的行为一起验证。只有 `create_time` 的关联、会话、日志实体自行声明该列，不增加无用的继承层级。
- 事务注解放在具体 Service 类的公共方法；不要只标在接口或 Controller 上。同类内部调用不会经过 Spring 代理，不能据此依赖事务或切面生效。
- 所有输入在边界校验。前端按钮可见性不构成接口授权；高风险授权操作在 Service 再核对可授予范围。不要将表实体暴露给 Controller、VO 或 `*-api`。

## 注释与文档

- 参考 [JeecgBoot 编码规范](https://help.jeecg.com/java/norm/code/)对类、方法及参数、实体字段和复杂逻辑的注释要求。公开接口、重要类和复杂业务方法写中文 JavaDoc；实体字段写业务含义，尤其说明状态取值、单位、是否持久化等非直观信息。普通的显而易见方法不为凑数量强制写注释。
- 方法 JavaDoc 先说明用途；有参数时写有意义的 `@param`，有返回值时写清 `@return` 的含义，存在重要业务异常时写 `@throws`。业务行内注释解释原因、边界条件和安全不变量，不逐行翻译代码。
- 不写自动生成的作者、日期、空 `@param` 或重复类名的注释。待办事项写明关联任务和完成条件；不提交调试说明或失效注释代码。
- 更改 Controller 路径、权限码、事务边界、授权范围或 Vben 响应形状时，同一变更更新架构文档。安全、审计和数据库迁移的非直观选择在代码附近说明原因。

[JeecgBoot 的控制器](https://github.com/jeecgboot/JeecgBoot/blob/main/jeecg-boot/jeecg-module-system/jeecg-system-biz/src/main/java/org/jeecg/modules/system/controller/SysDictController.java)和[实体](https://github.com/jeecgboot/JeecgBoot/blob/main/jeecg-boot/jeecg-module-system/jeecg-system-biz/src/main/java/org/jeecg/modules/system/entity/SysUser.java)提供了实际注释例子。其中也有空 `@return`、`@Author`、`@功能` 等历史写法；本项目不照搬，按 [JavaDoc 标准标签](https://docs.oracle.com/en/java/javase/22/docs/specs/javadoc/doc-comment-spec.html)填写有效内容。以下仅示意注释写法，具体方法以实现时的契约为准：

```java
/**
 * 系统用户管理服务，处理用户状态和角色分配。
 */
public class SysUserService {
    /**
     * 为用户分配角色，并校验操作人的可授予范围。
     *
     * @param operatorId 操作人用户 ID
     * @param userId 目标用户 ID
     * @param roleIds 拟授予的角色 ID 集合
     * @throws BusinessException 角色超出可授予范围，或请求变更内置超级管理员角色
     */
    public void assignRoles(Long operatorId, Long userId, Set<Long> roleIds) {
        // 实现省略
    }
}
```

实体字段及业务注释示例：

```java
/** 用户所属部门 ID。 */
private Long deptId;

// 唯一超级管理员角色只由首次引导分配，普通角色分配请求必须拒绝该角色。
validateAssignableRoles(roleIds);
```

像“查询菜单”“锁定角色行”这种只复述下一行代码的注释应省略。

## 接口输入、异常与日志

- Controller 使用 Bean Validation 校验 DTO；分页大小设置上限，批量 ID 数量设置上限，排序字段与方向使用白名单。Service 再校验角色可授予范围、菜单层级及其他依赖数据库状态的规则。不要将客户端提交的实体直接交给 Mapper 做全字段更新。
- 管理接口沿用 Vben 契约和统一 `Result<T>`。输入错误返回 HTTP 400，未认证返回 401，已认证但无权返回 403，唯一约束等资源冲突返回 409，未处理的服务端错误返回 500；响应中的 `code` 使用稳定的非零业务码，`message` 不暴露 SQL、堆栈或敏感数据。刷新接口保持架构设计规定的成功响应特例。
- 只在能处理的层捕获异常；捕获后仍需回滚的业务异常不得被吞掉。`GlobalExceptionHandler` 统一映射可预期异常与未知异常，未知异常在服务端记录堆栈，客户端只接收安全摘要。
- 使用 SLF4J 参数化日志和请求 `traceId`，避免同一异常在多层重复打印。登录日志写 `sys_login_log`，关键操作日志写 `sys_operation_log`；不得记录初始/临时/新旧密码、专用改密凭据、验证码 ID/答案、token、完整敏感请求体或未经脱敏的个人信息。日志保留期按部署环境与合规要求确定，不照搬手册中的固定天数。

## 数据与安全

- Flyway 是表结构变更入口；不修改已经执行的迁移。新增脚本使用全项目唯一版本号，以真实 MySQL 验证迁移、Mapper、字段映射、唯一约束与索引。字段命名及表级例外见架构设计。
- MyBatis-Plus 和自写 SQL 都不得拼接用户输入的值；自写 Mapper 使用参数绑定，动态列名和排序字段只从服务器端白名单选取。`sys_user.password` 虽沿用常见列名，内容只能是带盐的单向哈希；普通列表/详情查询和 VO 不得带出该列，也不能带出 refresh token 哈希。
- 业务唯一性由数据库唯一约束兜底，Service 提供可理解的冲突提示；不能只靠“先查再写”。索引以实际授权查询和分页查询为依据，建立后用查询计划与真实 MySQL 集成测试验证，不机械套用固定 JOIN 数量或分库阈值。
- JWT、数据库、Redis 及 OSS 等真正的密钥从受控运行环境读取，不提交到代码、配置样例、迁移脚本或日志。开发环境 MySQL/Redis 密码按约定为 `123456`，只放在被 Git 忽略的本地环境或受控密钥文件；生产另设密码。约定的临时密码 `12345678` 不是长期密钥：只在创建用户、管理员重置和显式启用的首次超管引导时使用，入库时加盐哈希，绝不写入日志或 HTTP 响应。后端必须执行接口鉴权、敏感字段脱敏和请求参数校验；带 Cookie 的刷新与退出接口按架构设计处理来源校验与 CSRF。
- `must_change_password` 为真时，只能使用短时效专用改密凭据完成改密，不得签发普通 access/refresh，也不得通过普通鉴权进入系统页面或 API。首次管理员引导由 `ADMIN_BOOTSTRAP_ENABLED` 显式控制，创建后及时关闭；若开关关闭而数据库为空，启动必须失败，不自动重建默认账号。
- 新密码由后端统一校验至少 8 个字符，拒绝常见/已泄露密码及与当前密码相同的值；前端规则与错误提示必须一致。本人改密、初次改密和管理员重置均递增目标用户 `authVersion` 并撤销其 refresh 会话。本人改密和首次改密后前端清理令牌并跳登录页；管理员重置他人密码时，仅目标用户的旧会话失效，操作管理员留在当前页。
- 登录页的图形验证码必须由后端签发并校验。验证码 ID 随机生成，答案只放带 2 分钟 TTL 的 Redis；校验时一次性原子消费，错误、过期或重复提交均拒绝。匿名获取验证码与登录接口使用 Redis 原子计数和 TTL 按可信客户端 IP/账号维度限流；Redis 故障不得绕过校验与限流。正常登录的当前用户最小快照也写 Redis，但接口鉴权仍以 MySQL 状态、授权版本和令牌族为准；详见[Redis 与环境配置设计](../架构设计/Redis与环境配置.md)。不得使用仅在浏览器校验的滑块代替服务端校验。
- 阿里云 OSS 凭证只在后端运行环境读取，优先使用 RAM 角色；Object Key 由服务端生成。业务上传入口先校验当前身份、文件用途、大小和实际内容类型，再调用公共存储能力。头像使用独立的公共读 Bucket，数据库 `sys_user.avatar_url` 保存后端生成的长期 HTTPS URL；公共读只允许匿名读取，写入和删除仅授权后端。替换头像时仅允许从已配置的头像域名和路径前缀下的旧 URL 提取 Key；不接受客户端任意 URL 或 Key 作为可读、可删、可绑定的对象。私有附件另用私有 Bucket 与短时效签名 URL，不把签名 URL 永久存库；长期 AccessKey 不得进入前端配置。

## 测试与验收

- 单元测试应自动化、相互独立、可重复执行，覆盖关键规则的正常、边界、拒绝和并发场景；集成测试使用真实 MySQL 验证 Flyway、Mapper、事务与 HTTP 响应。不要为了达到固定覆盖率数字写镜像实现的测试。
- 新增系统功能时核对菜单节点的页面查询码、按钮操作码、目录祖先、`@PreAuthorize`、Service 二次授权、实际落库的操作审计和 `authVersion`；覆盖孤立按钮授权拒绝、唯一超管账号保护及内置角色授予拦截、验证码一次性消费与限流、固定临时密码仅能进入改密流程、改密后会话失效与重新登录、引导开关关闭后的空库拒绝启动、refresh 并发提交与重放、401/403、Vben 的响应形状及权限变更后的令牌失效。前端同页和多标签页协调在 T14 做浏览器测试。涉及 OSS 时再覆盖文件大小/类型、本人绑定、头像 URL 匿名可读但不可写、旧对象及失败清理；私有附件另测签名访问。具体用例见架构设计的验收矩阵。
- 新增业务模块时核对 `*-api` 契约、启动装配和全局 Flyway 版本序列。`...IT` 类型测试需配置 Maven Failsafe 在 `verify` 阶段运行。

## IDEA、格式与构建

- 以聚合 `pom.xml` 打开工程；Project SDK 和 Maven Runner JDK 均设为 Java 21。依赖版本由父 `pom.xml` 管理，不靠个人 IDEA 配置补依赖。
- 启用 IDEA 的 EditorConfig 支持，以工程根目录 `.editorconfig` 为准：UTF-8、LF（Windows 批处理文件为 CRLF）、文件末尾换行；Java 用 4 空格，XML/YAML/JSON/Markdown/SQL 用 2 空格。禁用通配符 import，修改后格式化并优化 import，避免无关的大面积格式差异。
- 仅提交团队需要共享的 IDE 配置，不提交个人工作区状态、绝对路径、凭据或生成产物。
- 提交前运行 Maven Wrapper 的 `verify`：Windows PowerShell 用 `./mvnw.cmd verify`，其他环境用 `./mvnw verify`。需要 MySQL 的集成测试按工程测试配置启动环境；交付时说明实际执行的检查及限制。
