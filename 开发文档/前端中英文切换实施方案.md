# 前端中英文切换实施方案

## 目标

在目标应用 `frontend/apps/web-antdv-next` 中提供一致的简体中文与英文界面。切换语言后，当前页面、导航、表单、校验、通知和确认弹窗都应同步更新，不能出现截图中的中英文混杂。

## 现状与原因

- 应用已使用 Vben locale 初始化、语言切换控件、AntdvNext locale 与 Day.js locale；偏好配置默认 `zh-CN`。
- `src/locales/langs/zh-CN` 与 `en-US` 已包含部分认证和系统管理键，但覆盖不完整。多个产品页面仍将中文直接写在 Vue/TypeScript 文件中，语言切换无法替换这些字符串。
- 后端动态菜单标题由接口返回中文；前端目前直接用于侧栏、标签和面包屑。部分个人中心操作及校验提示也未使用 locale key。
- `zh-TW` 目录只有不完整语言文件，不属于当前核心支持语言，不作为本次第三种语言扩展。

## 已确认的范围

- 只支持 `zh-CN` 与 `en-US`，保留现有中文默认值和语言偏好持久化行为。
- 覆盖目标应用的框架界面、认证与首次改密、工作台、个人中心、七个系统管理页面（用户、角色、菜单、部门、字典、登录日志、操作日志），以及这些页面触发的校验、空状态、确认框、通知和错误提示。
- 使用现有 Vben/AntdvNext/Day.js locale 能力；应用自己的文案统一维护在 `src/locales/langs/{zh-CN,en-US}`，避免把文案继续硬编码在业务组件。
- 动态菜单按稳定路由路径或权限标识映射到前端 locale key，不改菜单 API、数据库种子或后端返回结构。未知菜单继续显示接口原始标题，防止自定义菜单名称丢失。
- 业务数据及用户自行填写的姓名、部门名、备注、字典项等保持原值，不做翻译。受支持的后端错误码可映射为本地化提示；未知错误使用相应语言的通用失败提示。
- 不恢复 Playground/已清理演示页面，也不扩展繁体中文。

## 实现约束

- 中英文键结构保持一致；用自动化检查发现缺键、额外键或结构类型不匹配。
- 页面在运行时切换语言后，菜单、标题、表格列、动态表单 schema 和校验消息应重新计算；不能要求刷新页面。
- 切换后 AntdvNext 日期/表单组件和 Day.js 格式化使用同一语言。
- Vben 框架已有的搜索、语言切换提示、退出确认等公共文案优先复用官方 locale；产品自有文案使用应用 locale 文件。
- 后端仍按当前 `Accept-Language` 传递语言偏好，但本次不修改后端的日志、持久化数据或业务响应契约。

## 验收标准

1. zh-CN 与 en-US 的应用 locale JSON 键结构完全一致。
2. 在登录页、工作台、个人中心和系统管理页面间切换语言，页面不刷新，导航、标题、表单字段、按钮、校验和通知均随之切换。
3. 登录/退出及个人中心确认对话框没有意外混用另一语言的固定文案。
4. 后端种子菜单和自定义未知菜单能正常展示；已知系统菜单随语言变化，用户输入的业务数据不被翻译。
5. 保存的语言偏好在重新打开应用后生效；AntdvNext 与 Day.js 语言一致。
6. 运行 locale 键覆盖测试、目标应用单元测试、typecheck 与 build；必要时用浏览器检查两种语言的关键页面并记录结果。

- 目标 Vitest 66 项、typecheck、生产构建均通过。构建有 BigInt target tolerated-transform 提示。
