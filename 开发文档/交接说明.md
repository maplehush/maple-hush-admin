## 已确定的主要决策

| 范围 | 当前约定 |
| --- | --- |
| 架构 | 模块化单体、一个可执行 Jar；业务代码按功能分包，统一 Controller → Service → Mapper 三层，不建微服务 |
| 后端模块 | `admin-base-core`、`admin-system-api`、`admin-system-biz`、`admin-system-start`；以后业务模块可按 `admin-mall-api`、`admin-mall-biz` 扩展 |
| 技术基线 | Java 21、Spring Boot 4.1.1、MyBatis-Plus 3.5.17 Boot 4 starter、MySQL 8.4 LTS、Flyway、Redis；T02 后补入 Lombok 1.18.48 与 Hutool 5.8.48 的 `core`、`captcha` 模块。T02 已用本机 MySQL 8.0.24 与 Redis 3.0.504 验证底座启动；T03 已在本机 MySQL 8.0.24 验证迁移，目标 MySQL 8.4 和部署留到后续任务 |
| 前端 | 使用 Vben 官方仓库的 `apps/web-antdv-next`；其他四个 UI 应用在 T01 移除，`playground` 作为演示代码保留至整个系统开发完成后再移除 |
| 系统功能 | 用户、角色、菜单、部门、字典、登录日志、操作日志；认证含用户名密码、图形验证码、首次强制改密和会话刷新；头像用阿里云 OSS |
| 数据 | 默认数据库名 `maple_hush_admin`；T03 已通过 Flyway V1/V2 建立 11 张业务表及迁移历史表，种入 1 个内置角色和 26 个菜单/按钮节点。T04 在本机开发库显式启用首次引导后创建了唯一 `admin` 超管账号，当前仍须以临时密码登录并完成首次改密。T05 的 V3 已增加 refresh 签发版本，当前开发库为 V3。两份 SQL 草案保留为设计输入，运行时只执行工程内迁移 |
| Redis 与配置 | T02 已接入 Redis 连接、字符串序列化、键前缀及健康检查；T04 已实现验证码、登录限流和最小用户快照，MySQL 保留 refresh 会话；T05 已完成轮换、重放撤销、退出和清理，T06 已实现有效授权与当前用户缓存读取。`dev` 同时供本机和开发 Compose 使用，连接地址由环境变量区分；MySQL 默认 `root/123456`、Redis 默认密码 `123456`，均可由环境变量覆盖；`test/prod` 必须显式提供独立凭据、JWT 密钥和公开 `AUTH_ALLOWED_ORIGINS` |
| OSS 参数 | 用户提供北京地域、`maple-hush` Bucket、公开域名及 `vben-admin-img/` 前缀，见[配置设计](./架构设计/Redis与环境配置.md#oss-头像配置)。AccessKey 仅供后端受控运行环境使用，不记录值、不放入任何 `VITE_` 前端变量；Bucket ACL 与实际上传尚未验证 |
