# 登录与权限

先在浏览器 Network 中找到真正失败的请求。HTTP 状态、业务 `code` 和前端处理异常是不同信息，不把所有失败都归为密码错误。

## ADMIN_BOOTSTRAP_ENABLED 能重置管理员密码吗？

**现象：** 修改引导开关、账号变量或重启应用后，原密码没有改变。

**排查：** 确认连接的是新数据库还是已有用户的数据库，是否已经创建管理员并完成首次改密。

**原因：** 引导仅在没有用户、没有超管持有者且显式启用时创建首个管理员。已有账号及其密码保存在数据库，正常启动不会覆盖。它与密码重置是不同操作。

**处理：** 空库首次启动按[首次管理员配置](/getting-started/configuration#flyway-与首次管理员)开启引导，完成改密后关闭。已有库使用保存的账号密码；普通用户忘记密码时由有权限的管理员通过重置密码功能处理。唯一超管丢失密码属于专门维护恢复场景，不用改引导变量或直接写入明文密码解决。

**核对结果：** 关闭引导后，原有账号仍能用已保存的新密码登录。重建前后端应用不会重置持久化数据库里的密码。

## 验证码明明看对了，为什么仍然无效？

**现象：** 登录响应出现 `CAPTCHA_INVALID`，或提交一次后继续使用相同图片失败。

**排查：** 确认本次提交的 `captchaId` 对应当前图片，图片是否放置过久，是否重复提交；同时检查是否有 Redis 依赖错误。

**原因：** 当前验证码有效期为两分钟，并采用一次性消费。不能假设账号密码错误后同一验证码仍可以重复提交。

**处理：** 获取新验证码后重新填写，避免重复点击；依赖错误按[启动与配置](./startup.md)处理。遇到频率限制应稍后再试，不连续刷新轰击验证码接口。

**核对结果：** 新图片与 ID 一致；若接下来收到其他错误，按新的错误类型处理，不把它继续当验证码问题。

## 登录 code 为 0，为什么没有进入工作台？

**现象：** 登录接口返回成功，但页面进入改密流程，或仍停留登录页并提示会话/登录处理异常。

**排查：** 先看响应 `data` 是需要改密还是正常会话，再看控制台和后续请求；不要仅凭 `code = 0` 判断整个登录流程完成。

**原因：** 首次登录可能只取得专用改密凭据；正常登录之后还涉及前端会话处理、用户信息与菜单加载。历史版本曾在 HTTP 页面因依赖 `crypto.randomUUID` / Web Locks 导致登录后异常，当前源码已经移除这项硬性依赖。当前浏览器仍需允许项目使用的存储能力。

**处理：** 需要改密时按[首次登录流程](/getting-started/first-run#_3-首次登录并修改密码)完成改密并重新登录；前端异常时核对实际运行产物是否包含修复，关闭旧标签页后重新打开，并检查浏览器是否限制站点存储。若后续 API 失败，按具体请求继续排查，不直接重置密码。

**核对结果：** 正常会话可进入工作台；改密分支完成后可用新密码登录。HTTP 兼容修复不等于所有浏览器都已实测，也不改变后续正式服务器使用 HTTPS 的计划。

## 为什么菜单、按钮和接口权限表现不一样？

**现象：** 有页面但没有按钮、菜单完全不显示，或按钮可见但 API 返回 `FORBIDDEN`。

**排查：** 按下面几种现象分别检查，确认使用的是当前账号：

| 现象 | 优先核对 |
| --- | --- |
| 菜单不显示 | 菜单与祖先状态、角色状态和授权、有效菜单返回结果 |
| 页面无法加载 | component 与实际 Vue 文件映射、后端组件允许列表 |
| 按钮不显示 | 按钮使用的权限码与当前有效权限码 |
| API 返回 40300 | 接口权限、Service 目标范围及受保护数据规则 |

**原因：** 路由组件、菜单、按钮和服务端授权职责不同。前端显示不代表后端必定允许操作；授权变更也可能使旧会话失效。

**处理：** 对照[菜单与权限](/development/permissions)检查配置与代码中的权限码，修改后重新登录加载当前授权。不要通过取消 `@PreAuthorize` 或只隐藏按钮处理接口拒绝。

**核对结果：** 菜单、按钮与当前授权一致，无权限账号直接请求接口仍会被拒绝。
