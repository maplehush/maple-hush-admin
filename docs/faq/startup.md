# 启动与配置

以下问题以[本地源码启动](/getting-started/)为前提，默认前端端口 5999、后端端口 8080，具体以实际启动输出为准。

## 写了 .env，为什么后端还是使用原配置？

**现象：** 在仓库根或 backend 新建 `.env`，修改连接参数后启动 Jar，应用仍连接旧地址。

**排查：** 确认启动方式是 `java -jar`、IDE 还是 Compose，并检查参数是否配置到了实际启动进程。不要把环境变量的值完整打印到日志中。

**原因：** 直接启动 Jar 不会自动读取这些 `.env` 文件。Compose 的变量加载、Vite 的 `.env*` 和 Java 进程环境是不同机制；已经打开的 IDE 也不一定继承另一个终端的新变量。

**处理：** Jar 启动在同一终端设置环境变量；IDE 启动在对应运行配置设置变量和 dev profile，然后重启后端。具体参数见[本地配置](/getting-started/configuration#后端配置如何加载)。

**核对结果：** 新进程激活预期 profile，并连接预期服务。仅改变运行参数时不必重新编译 Java 源码。

## MySQL 或 Redis 连接失败，先检查什么？

**现象：** 后端启动或验证码请求出现连接失败、认证失败，或必要依赖不可用。

**排查：** 区分日志中的连接超时/拒绝连接、账号认证失败、数据库不存在和迁移失败；分别核对实际主机、端口、账号及库名。`localhost` 指运行应用的机器或所在网络环境，不能默认代表另一台机器。

**原因：** 工程默认值不会安装服务、创建数据库或修改现有服务密码。连接失败的具体原因要以该次日志为准；Redis 也参与验证码和限流，不能只确认 MySQL 可用。

**处理：** 按实际服务填写配置并重启后端；数据库本身需提前创建，表结构交给 Flyway。开发 Redis 没有密码时，按[Redis 连接说明](/getting-started/configuration#redis-连接)显式覆盖默认密码，不只设置一个可能被终端删除的空环境变量。

**核对结果：** 后端正常启动，readiness 为 UP，验证码接口成功。若仍有错误，保留脱敏后的首个异常继续定位，不清空数据库或 Redis 试错。

## 换了前后端端口，为什么请求或登录失败？

**现象：** 页面可以打开，但 `/api` 连接失败，或登录相关请求返回来源校验错误。

**排查：** 查看实际前端 URL、后端监听端口、Vite 代理目标，以及失败请求的 HTTP 状态和业务码。代理不可达与来源校验失败需要分别处理。

**原因：** 默认代理指向 `127.0.0.1:8080`；允许的前端 Origin 默认包含 5999。只改一端端口不会同步修改另一端。当前 `VITE_API_PROXY_TARGET` 由 `vite.config.ts` 从启动进程环境读取。

**处理：** 在前端启动终端设置代理目标，重启 Vite；后端同步 `SERVER_PORT` 和实际 `AUTH_ALLOWED_ORIGINS` 后重启。按[自定义端口或后端地址](/getting-started/first-run#自定义端口或后端地址)操作，流程中固定使用同一个主机名。

**核对结果：** `/api` 到达预期后端，来源校验通过。不要通过关闭权限或 CSRF 校验解决端口配置问题。

## Knife4j 和错误码说明在哪里？

**现象：** 找不到接口文档，或打开文档后不知道在哪里查公共错误码。

**排查：** 确认后端已启动、实际端口及 profile；区分整个页面打不开和页面已打开但未找到说明。

**原因：** 文档默认关闭，仅开发、测试配置开放，生产关闭；公共错误说明集中在文档首页，不会在每个接口下重复展示完整码表。

**处理：** 本地 dev 默认访问 `http://127.0.0.1:8080/doc.html`，OpenAPI 为同端口 `/v3/api-docs`；在 Knife4j「主页」查看通用错误响应，也可直接阅读[公共错误码](/standards/api#公共错误码)。改了端口就使用实际端口。

**核对结果：** dev 文档页可访问，首页可查统一说明。生产环境没有文档入口属于既定配置，不为调试临时放开。
