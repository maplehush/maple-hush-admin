# 项目简介

Maple Hush Admin 是基于 Vue、Vben 和 Spring Boot 的后台管理基础项目，为业务系统提供用户、角色、菜单、部门、字典、日志和认证能力，作为二次开发的起点。

前后端代码、文档与部署配置保存在同一个 Git 仓库。前端以 Vben 的 `apps/web-antdv-next` 为目标应用，后端采用四个 Maven 模块，最终运行一个 Spring Boot 进程。

## 适合谁使用

- 有 Java、Vue 基础，希望快速了解并运行项目的开发者。
- 需要管理后台基础能力，准备继续扩展业务模块的团队。
- 希望通过一个完整工程学习前后端联调、认证授权与模块化开发的读者。

阅读文档时，建议先了解[技术栈](./technology.md)，再查看[系统架构](./architecture.md)和[目录结构](./directory.md)。准备在本地运行时，按[快速开始](/getting-started/)的顺序操作。

## 已实现的功能

| 功能领域 | 当前能力 |
| --- | --- |
| 登录认证 | 用户名、密码、服务端图形验证码；首次登录强制修改初始密码 |
| 会话管理 | JWT access token、refresh token 轮换、退出、授权变更后的会话失效 |
| 用户管理 | 查询、新增、修改、删除、状态维护、角色分配、管理员重置密码 |
| 角色管理 | 角色维护、菜单授权及内置角色保护 |
| 菜单管理 | 菜单与按钮节点维护、动态路由、权限码配置 |
| 部门管理 | 部门树、增改删及关联删除保护 |
| 字典管理 | 字典类型与字典项维护、启用项查询、颜色与默认项配置 |
| 日志查询 | 登录日志、操作日志分页查询及保留清理 |
| 个人中心 | 本人资料修改、本人改密与头像更新 |
| 文件上传 | 后端校验与上传配额控制，接入阿里云 OSS |
| 接口调试 | 开发和测试环境的 Knife4j Next / OpenAPI 文档 |

系统管理包含用户、角色、菜单、部门、字典、登录日志和操作日志七个管理页面；个人中心是独立入口。功能是否可用还取决于当前账号权限、环境配置和外部服务。

## 权限模型

项目按用户、角色、菜单与权限码组织授权：

- 用户通过角色获得菜单与操作权限。
- 前端根据后端返回的菜单生成动态路由，并按权限显示按钮。
- 后端独立校验接口权限，隐藏按钮不能替代服务端授权。
- 普通用户可以在未分配角色时创建；没有业务授权不等于获得系统管理权限。

具体代码入口见[认证与授权职责](./architecture.md#认证与授权职责)。

## 工程特点

- **模块化单体**：按职责拆分 Maven 模块，避免一开始就引入多服务部署。
- **前后端分离**：通过同源 `/api` 交互，页面与业务接口各有清晰入口。
- **统一约定**：响应、分页、错误处理、数据库迁移和权限码有统一实现。
- **文档与代码同仓**：面向使用者的教程放在 `docs/`，内部设计与验收资料保留在 `开发文档/`。
