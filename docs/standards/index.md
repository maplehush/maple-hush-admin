# 开发规范

本栏目说明参与 Maple Hush Admin 二次开发时需要遵守的约定。第一次新增功能，先跟随[开发指南](/development/)走通模块、接口、页面和权限，再用本栏目检查实现。

## 阅读顺序

| 页面 | 主要解决的问题 |
| --- | --- |
| [后端规范](./backend.md) | 模块依赖、分层、命名、事务、校验和日志 |
| [前端规范](./frontend.md) | 目录、组件适配、类型、表单、国际化和格式 |
| [接口规范](./api.md) | 请求、响应、分页、ID、错误码和认证 |
| [数据库规范](./database.md) | 字段、约束、索引和 Flyway 迁移 |
| [Git 协作](./git.md) | 分支、提交、检查与敏感文件管理 |

## 适用范围

- 后端约定适用于 `backend/` 的 Java、SQL 与配置。
- 前端约定适用于 `frontend/`，当前目标应用为 `apps/web-antdv-next`。
- `docs/` 是独立文档工程，使用自己的依赖、锁文件和构建命令。
- 工作区中的参考工程用于查阅，不能作为当前产品接口和功能已经存在的依据。

接口、字段或配置发生变化时，同时更新调用方和相关使用文档。新规则如果与现有代码不一致，应先确认影响并统一约定，避免由某一端自行猜测。

## 共同原则

### 保持职责清楚

Controller 处理 HTTP 边界，Service 承载业务规则，Mapper 处理持久化；前端页面负责交互，API 文件负责请求，适配器负责组件协议。共享逻辑确有复用需求时再提取，避免为简单操作增加多层转发。

### 使用已有能力

普通业务请求复用 `requestClient`，表单和列表复用 Vben 封装，错误使用公共错误码，数据库升级使用 Flyway。这样新增功能能继续使用已有的认证、异常处理和交互机制。

### 校验与权限由后端兜底

前端校验改善输入体验，按钮隐藏改善操作体验。后端仍必须校验参数、操作权限、目标数据范围和并发约束。不能通过构造一个 HTTP 请求绕过限制。

### 记录能够证明的结果

提交说明写清修改内容、实际检查命令及结果。没有运行的构建、测试、迁移或部署，不写成“通过”。教学示例也需要在接入自己的项目后验证。

## 提交前检查

| 检查项 | 应当确认的内容 |
| --- | --- |
| 功能边界 | 本次变更解决一个明确问题，没有夹带无关重构 |
| 接口一致 | 路径、字段、ID 类型、权限码及响应与调用方一致 |
| 数据安全 | 没有绕过授权；敏感值不进入响应、日志和 Git |
| 数据变更 | 新迁移版本未冲突，历史迁移未修改，约束与索引合理 |
| 交互完整 | 加载、失败、重复提交、空数据和语言切换有对应处理 |
| 检查结果 | 按改动范围执行检查并记录；测试覆盖关键行为与拒绝路径 |
| 文档同步 | 使用方式、配置或契约变化已反映到文档 |

## 检查命令按工程执行

前后端命令见各自规范页，当前 CI 的检查范围见 [Git 协作](./git.md)。仅修改文档时，在仓库根目录执行：

```sh
pnpm --dir docs build
```

随后预览受影响页面，检查导航、链接、代码块和表格。编写文档本身不需要启动数据库、Redis 或业务应用。
