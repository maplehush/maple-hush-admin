# Development Guide

This chapter uses “Announcement Management” as a teaching example to explain how to add business modules, database tables, APIs, and administration pages to the project, and connect them to the existing menus and permissions.

::: info Example scope
Announcement Management is not an existing repository feature. The file paths, tables, and APIs below are additions for your own development. Integrate them on your own development branch.
:::

Complete [Getting Started](/en/getting-started/) first, then follow this sequence on your own development branch and development database.

## Conventions used throughout this chapter

| Item | Example in this chapter |
| --- | --- |
| Maven modules | admin-notice-api, admin-notice-biz |
| Java package | com.maplehush.admin.notice |
| Database table | biz_notice |
| API prefix | /api/notice |
| Page URL | /content/notice |
| Page component key | /notice/list |
| Frontend page | frontend/apps/web-antdv-next/src/views/notice/list.vue |
| Permission codes | system:notice:list / create / update / delete (use the full prefix for each) |

Current system menu validation requires `system:resource:action`, so the example uses `system:notice:*`. Here, `*` summarizes the four operations; do not enter a wildcard in the menu. Using a different permission namespace requires separate changes to backend validation and the related conventions.

## Example features and fields

The example covers creating, editing, deleting, viewing details, and paginated queries. It does not add rich text, attachments, approval, or scheduled publishing.

| Field | Frontend / HTTP type | Rules |
| --- | --- | --- |
| id | string | Auto-incrementing database bigint; a positive decimal integer string over HTTP |
| title | string | Required; trim leading and trailing whitespace; up to 200 characters |
| content | string | Required plain text; up to 5000 characters |
| status | 0 or 1 | 0 disabled, 1 enabled; the administration list can display both |
| createTime / updateTime | string | Generated by the backend in yyyy-MM-dd HH:mm:ss format |

Enter announcement content as plain text and display it with Vue text interpolation, without `v-html`. In this example, `status=1` means enabled; it does not make the content public to anonymous users.

## API contract

| Method | Path | Parameters / returned data | Required permission |
| --- | --- | --- | --- |
| GET | /api/notice/list | page, pageSize, title, status; returns items / total | system:notice:list |
| GET | /api/notice/{id} | Returns one NoticeVO | system:notice:list |
| POST | /api/notice | title, content, status; returns a string id | system:notice:create |
| PUT | /api/notice/{id} | Submit all of title, content, status; returns null | system:notice:update |
| DELETE | /api/notice/{id} | Returns null | system:notice:delete |

Page numbering starts at 1. pageSize ranges from 1 to 100 and defaults to 20. Title filtering uses a partial match; status uses an exact match. Sort order is fixed: creation time descending, then ID descending. Missing details and updates/deletions that match no record return NOT_FOUND.

Standard responses use `Result<T>`, with `code=0` on success. The frontend requestClient already unwraps the response. Pages receive data directly and must not read response.data again.
